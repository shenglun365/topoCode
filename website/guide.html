TopoCode 使用文档

版本: 0.1.0 beta | 开发者邮箱: topocode@163.com

隐私说明：除您自行配置的云端 LLM API 外，TopoCode 的代码解析、图计算、架构分析、Web 文档服务等所有功能均在本地运行，项目源码和解析数据不会上传至任何外部服务器，确保您的数据隐私安全。

一、产品简介

TopoCode 是一款面向开发者的源码架构分析与学习工具。它通过静态代码解析、依赖图计算、社区发现算法和 AI 辅助分析，帮助开发者快速理解陌生项目的架构设计、模块划分和代码组织方式。

核心功能

  • 项目导入与管理 — 支持本地目录导入、文件树浏览、分组管理
  • 多语言代码解析 — 基于 Tree-sitter 的 AST 解析，支持 18+ 编程语言
  • 架构可视化 — 依赖图/调用图/社区结构图，支持交互式浏览
  • 社区发现 — Louvain/Leiden 算法自动识别代码模块结构
  • AI 架构分析 — LLM 驱动的工作流，自动分析组件功能、生成架构概览文档
  • 交互式 AI 助手 — 通过本地 Web 端口提供浏览器端对话界面
  • Web 文档服务 — 本地 HTTP 服务，浏览器中浏览架构文档

三、安装与启动

3.1 安装前端依赖

Electron 安装时会从 GitHub Releases 下载二进制文件，建议设置国内镜像加速：

# 设置 Electron 国内镜像
export ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
# Windows: set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/

# 使用国内 npm 镜像
npm config set registry https://registry.npmmirror.com
npm install

3.2 创建 Python 虚拟环境并安装依赖

# 在项目主目录创建虚拟环境
python3 -m venv .venv

# 激活虚拟环境
# Linux / macOS:
source .venv/bin/activate
# Windows:
# .venv\Scripts\activate

# 安装后端依赖（国内镜像）
cd backend-core
pip install -r requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple

3.3 运行开发模式

# 启动 Vite dev server + Electron（自动启动 Python 后端）
npm run dev

# 仅启动 Vite 前端（浏览器开发）
npm run dev:vite

3.4 构建生产版本

npm run build
npm run dist:linux   # Linux (.AppImage/.deb/.rpm)
npm run dist:win     # Windows (.exe)
npm run dist:mac     # macOS (.dmg/.zip)

四、项目导入

截图占位: images/guide/zh/project-import.png
  1. 进入首页，点击导入项目按钮
  2. 选择本地源码目录，系统自动扫描并导入

导入过程显示全局遮罩进度。大型项目（数万文件）可能需要 1-5 分钟。

失败处理

现象处理

进度卡住检查项目目录，排除 node_modules 等目录
文件数为 0确认目录包含支持的语言文件

五、创建分析任务

截图占位: images/guide/zh/create-task.png
  1. 在左侧文件树中点击项目节点
  2. 点击分析标签页 → 创建任务
  3. 填写任务名称、分析类型、分析范围和文件过滤条件
  4. 点击确定创建任务，然后点击运行执行分析

六、代码解析 (AST)

解析流程

  1. 文件扫描 — 遍历项目文件树，识别源代码文件
  2. AST 解析 — Tree-sitter 语法解析，提取符号定义和引用关系
  3. 图构建 — 构建符号图和依赖图
  4. 社区发现 — Louvain/Leiden 算法聚类为"社区"（逻辑模块）

耗时预估（单并发全量解析）

项目规模文件数AST 解析图+社区合计
小型< 5001-5 分钟30s-2 分钟2-7 分钟
中型500-5K10-30 分钟2-10 分钟15-40 分钟
大型5K-50K1-3 小时10-30 分钟1.5-4 小时
超大型> 50K3-8 小时30-60 分钟4-9 小时

重跑机制

AST 解析任务成功后不可直接重跑，这是为了维护分析数据的一致性。需要重新解析时，请删除原有任务后创建新任务。

截断执行

创建任务时指定子目录作为分析范围，系统仅解析该目录及其依赖文件。再次运行同一任务时，自动跳过已完成的文件。

失败处理

现象处理
任务一直 pending重启应用后重试
运行中卡住减少分析范围，排除大文件目录
符号数为 0检查项目语言是否被支持（18+ 主流语言）

八、AI 辅助分析

8.1 生成架构概览

在报告视图中点击生成架构概览，系统收集社区分析结果和文件摘要，调用 LLM 生成 Markdown 格式架构文档。

8.2 组件分析

在社区结构图中选择特定社区，可以查看组件详情、让 LLM 分析组件功能、为社区命名。

8.3 组件重跑与模型切换

对某组件分析结果不满意时，无需重新运行整个任务：

  1. 右键点击目标组件节点 → 选择"AI 分析组件"或"重新分析"
  2. 系统仅对该单个组件重新发起 LLM 分析，不影响其他组件

重跑前可在设置 → 模型配置中切换到性能更高的模型，新模型立即生效。

8.4 耗时预估（单并发）

预摘要（每 100 个文件）：本地模型 30-60 分钟，云端模型 5-15 分钟。

组件分析（每个社区）：本地模型 3-8 分钟，云端模型 30s-2 分钟。

完整流水线：小型项目（5-10 社区）本地 30-90 分钟，大型项目（30-100 社区）本地 6-20 小时。

组件分析当前为单请求串行处理，不支持内部并发，建议本地模型过夜运行。

8.5 截断与跳过已完成

不使用 --force 时再次运行，自动跳过已完成的部分；使用 --force 则忽略缓存全部重跑。

8.6 替代方案

访问 topocode.cn 注册，获取已预分析好的项目，可关联本地代码或直接浏览文档。

九、Web 文档服务

AI 助手交互界面和文档浏览均通过本地 Web 服务提供，默认地址 http://localhost:3456：

  • / — 项目文档首页
  • /doc — 文档查看器（支持 Mermaid / PlantUML 渲染）
  • /chat — AI 对话界面（浏览器即可使用，无需 Electron）

可通过设置 → 通用设置修改 HTTP 端口。

十、AI Chat 对话

10.1 开始对话

访问 http://localhost:3456/chat → 新建会话 → 输入问题。

10.2 Chat 命令

命令说明参数
/overview生成架构概览--force
/analyze_components逐组件 LLM 分析--force; -L zh/en
/presummary文件预摘要--force

10.3 跨会话引用

持久化的对话可作为上下文跨会话引用：在 A 会话中输入 @session:xxx 引用 B 会话内容。

十一、基于知识库的分析对话

知识库目前用于持久化存储和管理架构分析文档。AI Chat 对话已自动持久化，可在会话中通过 @session:xxx 引用其他会话内容。对话内容尚未规范化结构化，当前未纳入知识库，未来版本会增加结构化提炼后入库的能力。

十二、LLM 配置建议

用途推荐方案
架构解析（Agent 工作流）本地模型 Qwen3.6-9B-Q4 量化及以上，建议 RTX 4060 Ti 16GB 以上
AI Chat 对话云端模型 DeepSeek V4 Flash（高性价比），或其他兼容 OpenAI 协议的服务

在设置 → 模型配置中添加模型，支持 Ollama / OpenAI 协议兼容 / LM Studio 等。

十三、常见问题

端口冲突

修改设置 → 通用设置中的 HTTP 端口，或通过环境变量 ZMQ_DEALER_PORT / ZMQ_PUB_PORT 指定。

后端异常

查看日志目录：Linux ~/.topocode/logs/，macOS ~/Library/Application Support/TopoOne/logs/。

TopoCode Usage Guide

Version: 0.1.0 beta | Developer Email: topocode@163.com

Privacy Notice: Except for user-configured cloud LLM APIs, all features of TopoCode — code parsing, graph computing, architecture analysis, web document service, etc. — run locally. Your project source code and analysis data are never uploaded to any external server.

1. Introduction

TopoCode is a source code architecture analysis and learning tool for developers. Through static code parsing, dependency graph computation, community detection algorithms, and AI-assisted analysis, it helps developers quickly understand the architecture of unfamiliar projects.

Core Features

  • Project Import — Local directory import, file tree browsing, group management
  • Multi-language Parsing — Tree-sitter based AST parsing for 18+ languages
  • Architecture Visualization — Dependency/call/community structure graphs with interactive browsing
  • Community Detection — Louvain/Leiden algorithms for automatic module identification
  • AI Architecture Analysis — LLM-powered workflows for component analysis and overview generation
  • Web AI Chat — Browser-based AI assistant via local web service

7. Architecture Visualization

Screenshot placeholder: images/guide/en/community-graph.png

Interactive community structure graph with drag, zoom, drill-down, and context menu. Toggle between include/call graphs, heatmap, and file mode.

8. AI-Assisted Analysis

Single-Component Re-analysis

Right-click a community node → select "AI Analyze Component" to re-run analysis on that component only. Switch to a different model in Settings first if needed.

Time Estimates (single concurrency)

Pre-summary (per 100 files): local 30-60 min, cloud 5-15 min.

Component analysis (per community): local 3-8 min, cloud 30s-2 min.

Component analysis runs as single-request serial processing. Without --force, re-running skips completed parts.

Alternative

Sign up at topocode.cn for pre-analyzed projects.

9. Web Document Service

Both the AI assistant and document browser are served locally at http://localhost:3456: / (project list), /doc (document viewer), /chat (AI chat).

10. AI Chat

Visit http://localhost:3456/chat → create a session → start chatting. Supports slash commands: /overview, /analyze_components, /presummary, /pipeline with --force and -L zh/en flags.

Cross-session reference: use @session:xxx in Session A to reference content from Session B.

11. Knowledge Base

The knowledge base stores architecture analysis documents. Chat conversations are auto-persisted and cross-referenceable via @session:xxx. Future versions will add structured ingestion into the knowledge base.

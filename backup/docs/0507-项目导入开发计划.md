### 1.2 数据库拆分架构 (已确认)

#### 拆分方案 (4 类独立 SQLite 文件)

所有数据库文件统一存放在 `~/.topoone/` 目录下。

| 数据库文件 | 命名规则 | 包含表 | 说明 |
|-----------|---------|--------|------|
| **主库** | `topoone.db` | `projects`, `model_configs`, `agent_configs`, `skill_configs`, `task_model_bindings`, `context_store` | 项目基本信息 + 全局配置 |
| **知识库** | `knowledge.db` | `knowledge_docs` | 跨项目共享，独立管理 |
| **会话库** | `sessions.db` | `coder_sessions`, `chat_messages` | 会话数据量大，独立管理 |
| **项目分析库** | `{project_id}.db` | 见下表 | 每个项目独立一个数据库文件，UUID 命名 |

#### 项目分析库表结构 (`{project_id}.db`)

| 表 | 说明 | 字段 |
|----|------|------|
| `source_files` | 源码文件列表 + 内容哈希 | id, file_path(相对路径), language, size, content_hash(MD5), parent_path, created_at, updated_at |
| `ast_data` | AST 解析结果（由解析模块写入，**仅保留最新**） | id, file_path, ast_json, version, parsed_at |
| `dependencies` | 项目源码依赖关系 | id, source_file, target_file, dep_type, created_at |
| `call_chains` | 函数调用关系 | id, caller_file, callee_file, caller_func, callee_func, line_number, created_at |
| `components` | 组件划分 | id, component_name, component_type, file_paths(JSON), description, created_at |
| `ai_qa` | AI 辅助解答记录 | id, question, answer, context_files(JSON), session_id, created_at |
| `project_config` | 项目级配置 | id, key, value(JSON), created_at, updated_at |

#### 项目路径管理规则 (Q3 补充)

| 规则 | 说明 |
|------|------|
| **相对路径存储** | `source_files.file_path` 存储相对于项目根目录的相对路径，不存储绝对路径 |
| **根目录可修改** | 项目导入后可修改源码根目录路径，路径变更时校验相对路径是否仍然有效 |
| **文件变更检测** | 通过 `content_hash(MD5)` 识别文件是否修改，变更时提示用户是否重新分析 |
| **路径变更提示** | 项目根目录变更后，检查相对路径下的文件是否存在，状态给与提示 |
| **高阶分析版本管理** | 组件图/依赖图/调用图等支持从 SQLite 导出为 graph 文件（JSON 格式），通过 Git 管理文件级别的版本 |
| **AST 仅保留最新** | `ast_data` 表每个 `file_path` 只保留当前最新的分析结果，不保留历史版本 |
| **全量备份/导入** | 所有 SQLite 数据支持备份为文件包，可导入到新环境（前提是本应用版本兼容） |
| **双独立状态标志** | `needs_resync`（路径变更触发）和 `has_file_changes`（内容变更触发）两者独立 |
| **路径校验时机** | 项目打开时默认校验路径变更 |
| **内容校验时机** | 读取具体文件列表/文件内容时校验文件内容变更并提示用户 |
| **手动全量比对** | 用户手动触发项目级的文件逐个变更比对 |

#### 拆分后的影响

| 影响范围 | 说明 |
|----------|------|
| `backend/sqlite_ctx.py` | 重构为 `MultiDBManager`，支持主库 + 知识库 + 会话库 + 动态项目库 |
| `backend/main.py` | `BackendApp` 使用 `MultiDBManager`，管理多个 DB 连接 |
| `backend/core_service.py` | 所有方法明确使用对应 DB；analysis 方法按项目 ID 路由到项目库 |
| `project.import` | 成功后创建 `{project_id}.db` 并初始化 6 张表 |
| `project.remove` | 成功后删除 `{project_id}.db` 文件 |
| `project.sync` | 写入项目库 `source_files` 表，使用相对路径 + MD5 哈希 |
| `project.getFileTree` | 从项目库 `source_files` 表读取 |
| `projects` 表 | 移除 `file_snapshots`（迁移到项目库），新增 `root_path`, `status`, `needs_resync`, `has_file_changes` 字段 |

#### P1: 功能缺失

| # | 功能 | 说明 |
|---|------|------|
| 5 | **导入无加载状态** | 导入大项目时用户无反馈 |
| 6 | **导入无错误处理** | 路径不存在/无权限/非目录等错误未展示给用户 |
| 7 | **文件树无懒加载** | 大项目一次性加载所有节点，性能差 |
| 8 | **文件树无搜索** | 无法按文件名搜索 |
| 9 | **文件树无文件大小格式化** | 后端返回字节数，前端未格式化为 KB/MB |
| 10 | **项目卡片无操作菜单** | 无法删除/同步/修改路径（需右键 + 按钮） |
| 11 | **项目视图无文件预览** | 点击文件无内容预览面板（右侧内联 + 可固定到 Tab） |
| 12 | **新手教程缺失** | 每次启动无引导（用户可永久关闭） |
| 13 | **示例数据缺失** | 无轻量级示例数据（安装程序自带，预留空结构） |
| 14 | **项目路径修改功能缺失** | 无法修改已导入项目的源码根目录 |
| 15 | **文件变更检测缺失** | 无法通过 content_hash 检测文件修改并提示用户 |
| 16 | **备份/导入功能缺失** | 无法备份/导入 SQLite 数据 |

#### P2: 后端优化

| # | 优化项 | 说明 |
|---|--------|------|
| 17 | **文件扫描未忽略构建产物** | `_scan_file_tree()` 不跳过 `node_modules`, `.git`, `dist`, `build` 等目录 |
| 18 | **语言检测取第一个而非最常用** | `_detect_language()` 遍历 lang_map 找到第一个匹配的扩展名就返回 |
| 19 | **文件树未增量更新** | `sync_project` 全量重建 file_snapshots，大项目慢 |
| 20 | **未支持 .gitignore 过滤** | 需解析项目 `.gitignore` 配置 |

## 五、风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据库拆分引入多连接管理复杂度 | 连接泄漏/性能下降 | MultiDBManager 统一管理，项目库懒加载+LRU(max=3) |
| 多窗口公共数据库读写竞争 | 写冲突/数据不一致 | SQLite WAL 模式 + 写操作加锁 + 跨窗口广播同步 |
| 大项目导入耗时 | 用户等待时间长 | 导入改为异步 + 进度推送 |
| 文件树节点数过大 | 前端渲染卡顿 | 懒加载（已确认） |
| 跨平台路径差异 | Windows/Linux 路径格式不同 | 后端统一用 `os.path` 处理，存储相对路径 |
| 特殊字符文件名 | 数据库存储/前端显示异常 | 增加输入校验 |
| 项目路径变更后文件丢失 | 用户数据丢失 | 变更前校验相对路径有效性，提示用户确认 |
| 备份/导入版本不兼容 | 数据损坏 | 导出时记录 schema 版本，导入时校验 |
| 后端进程与首窗口绑定 | 关闭窗口导致后端停止 | 后端独立生命周期 + 看门狗保活 |
| .gitignore 完整解析复杂度 | 解析错误导致漏扫/多扫 | 使用成熟第三方库或严格单元测试 |
| 项目级配置分散在项目库 | 配置迁移困难 | 导出时包含 project_config 表数据 |

# 风险识别与应对策略

> 技术风险、进度风险、外部依赖风险

---

## 1. 技术风险

### R1: Tree-sitter 语言覆盖不足

| 维度 | 说明 |
|------|------|
| **风险** | Tree-sitter 对 Go/Java 的支持成熟度低于 Python/JavaScript，可能无法提供足够精确的 AST |
| **影响** | Phase 2 代码分析功能对 Go/Java 项目的分析质量下降 |
| **概率** | 中 |
| **应对** | 1) 优先支持 Python 和 JavaScript；2) Go/Java 使用降级策略：解析失败时回退为正则匹配；3) 关注上游 tree-sitter-go/tree-sitter-java 更新 |

### R2: ChromaDB 嵌入式部署复杂度

| 维度 | 说明 |
|------|------|
| **风险** | ChromaDB 作为嵌入式向量数据库，Python 版本兼容和跨平台部署可能遇到问题 |
| **影响** | Phase 3 知识库向量检索无法正常工作 |
| **概率** | 中 |
| **应对** | 1) 锁定 ChromaDB 版本并充分测试；2) 备选方案：使用 SQLite 的 FTS5 全文搜索作为降级检索；3) embedding 模型使用轻量级 all-MiniLM-L6-v2 |

### R3: Electron + Python 子进程管理稳定性

| 维度 | 说明 |
|------|------|
| **风险** | Python 后端作为子进程运行，跨平台进程管理差异大，崩溃恢复策略可能不够健壮 |
| **影响** | 后端不可用时整个应用功能受限 |
| **概率** | 中 |
| **应对** | 1) 实现 Health Check 轮询 + 自动重启 (最多 3 次)；2) 前端展示明确的后端状态 (StatusBar)；3) 优雅降级：后端不可用时允许浏览已缓存数据 |

### R4: WebSocket 连接稳定性

| 维度 | 说明 |
|------|------|
| **风险** | 长时间运行的 WebSocket 连接可能因网络波动断开，影响流式 AI 回复和任务进度推送 |
| **影响** | Phase 4 AI 对话体验下降、Agent 任务状态丢失 |
| **概率** | 低 |
| **应对** | 1) 前端 WebSocket 管理器实现指数退避自动重连；2) 重连后自动恢复订阅；3) 关键状态通过 REST API 轮询兜底 |

### R5: Monaco Editor 体积与性能

| 维度 | 说明 |
|------|------|
| **风险** | Monaco Editor 打包体积 ~5MB，可能拖慢应用启动速度 |
| **影响** | 应用首屏加载变慢 |
| **概率** | 低 |
| **应对** | 1) Monaco Editor 懒加载 (仅 DocEditor 使用时加载)；2) 生产环境启用 Monaco 的 Web Worker；3) 备选：使用 CodeMirror 6 作为轻量替代 |

## 2. 架构风险

### R6: Phase 3 功能范围膨胀

| 维度 | 说明 |
|------|------|
| **风险** | Phase 3 (知识库) 集合了知识图谱 (D3力导向)、ChromaDB、Monaco 编辑器、动画播放器，单个 Phase 实现周期过长 |
| **影响** | Phase 3 可能成为瓶颈，阻塞 Phase 4 的开发 |
| **概率** | 高 |
| **应对** | 1) 拆分为 Phase 3a (知识库核心: 文档 CRUD + 四维筛选) 和 Phase 3b (图谱 + 动画 + 编辑器高级功能)；2) 动画播放器可延后到 Phase 3b 或独立 Phase |

### R7: Agent 协议兼容性

| 维度 | 说明 |
|------|------|
| **风险** | AgentService 要求 CLI Agent 遵守特定输出格式 (`[PROGRESS]/[LOG]/[RESULT]`)，外部 Agent 未必兼容 |
| **影响** | 外部 Agent 调度失败或状态解析错误 |
| **概率** | 高 |
| **应对** | 1) 提供 Agent SDK / 示例模板；2) 支持 Agent 输出格式自定义正则配置；3) 首批只支持内置 Agent，外部 Agent 逐步适配 |

---

## 3. 进度风险

### R8: 单人开发资源瓶颈

| 维度 | 说明 |
|------|------|
| **风险** | 31 个前端组件 + 6 个 Service + Electron 架构，全部由单人实现，战线过长 |
| **影响** | 开发周期远超预期 |
| **概率** | 高 |
| **应对** | 1) 严格按 Phase 顺序交付，每 Phase 产出可运行的最小可用版本；2) 优先实现核心路径 (P0)，推迟非核心功能；3) 复用原型代码 (prototype/ 下的 HTML/CSS/JS) |

---

## 4. 外部依赖风险

### R9: LLM API 服务可用性

| 维度 | 说明 |
|------|------|
| **风险** | 用户使用的云端 LLM API (OpenAI 等) 可能因网络/配额/服务故障不可用 |
| **影响** | Phase 4 AI 助手核心功能不可用 |
| **概率** | 中 |
| **应对** | 1) ModelService 实现多模型 fallback；2) 提供清晰的错误提示和重试机制；3) 本地模型 (Ollama) 作为备选，由用户自行安装 |

### R10: Electron 版本升级兼容性

| 维度 | 说明 |
|------|------|
| **风险** | Electron 大版本升级可能引入 breaking changes |
| **影响** | 构建失败、运行时错误 |
| **概率** | 低 |
| **应对** | 1) 锁定 Electron 主版本号；2) 定期跟进 release notes；3) CI 中增加 Electron 版本兼容性测试 |

# topocode 系统需求文档

针对你提出的“本地源码分析工具”开发构想，结合 Electron + Vue 技术栈以及 AI 驱动的核心思路，以下是为您整理的详细需求分析：

###  一、项目概述与核心目标
本项目旨在开发一款**本地化、插件化、AI驱动**的源码架构分析与可视化教学工具。核心目标是帮助开发者、架构师及学员通过多维度视角（静态AST、AI语义、动态动画）深入理解代码库的架构逻辑，并支持自定义教学动画的生成与演示。

### ️ 二、技术架构需求
*   **客户端框架**：采用 **Electron + Vue** 构建跨平台（Windows/macOS/Linux）桌面应用，确保本地文件系统的深度访问能力与流畅的GUI交互体验。
*   **可视化引擎**：
    *   **标准图表**：集成 **Mermaid** 和 **PlantUML** 渲染器，用于快速生成标准的流程图、时序图和类图。
    *   **高级动画**：集成基于 **D3.js** 自研的教学动画引擎，用于展示复杂的数据流向、模块交互及动态执行逻辑。
*   **AI与算法层**：
    *   **AST分析**：采用 **Python + Tree-sitter** 编写高性能的语法树解析插件，提供精准的静态代码结构提取。
    *   **大模型集成**：通过 Python 后端封装 AI 调用逻辑，支持灵活切换模型源。

###  三、核心功能需求

**1. 源码导入与插件化管理**
*   **项目导入**：支持一键导入本地代码仓库（文件夹），自动识别主流编程语言。
*   **插件化分析引擎**：
    *   源码分析能力需解耦为独立插件（如 Python AST 插件、Java 解析插件等）。
    *   支持热插拔，用户可根据项目语言按需启用对应的 Tree-sitter 解析器。

**2. 多维度架构分析**
*   **AI 语义分析（核心）**：
    *   利用大模型（LLM）对代码进行深度语义理解，自动生成模块依赖关系、核心业务逻辑描述及架构优缺点评估。
    *   支持自然语言问答（如：“请分析该项目的鉴权流程”），AI 基于代码上下文给出解答。
*   **静态结构分析**：
    *   基于 Tree-sitter 提取函数调用链、类继承关系、文件依赖图。
    *   生成基础的项目结构树与符号表。

**3. 多模态可视化展示**
*   **图表渲染**：将 AI 和 AST 分析的结果自动转化为 Mermaid 或 PlantUML 代码并实时渲染，支持导出为图片或 SVG。
*   **教学动画演示**：
    *   调用自有 D3 动画引擎，将静态的架构数据转化为动态演示（例如：模拟数据包在微服务间的流转过程）。
    *   支持用户自定义动画脚本，用于制作技术分享或教学课件。

**4. 灵活的 AI 模型配置**
*   **本地模型支持**：内置 Ollama 和 LM-Studio 接口适配，允许用户在本地离线环境下运行 Llama 3、Qwen 等开源模型，保障源码数据隐私。
*   **云端 API 支持**：支持配置 OpenAI、DeepSeek 等云端大模型 API Key，以获取更强的推理能力。
*   **模型切换**：在设置中可一键切换分析所使用的模型后端。

### ️ 四、非功能性需求
*   **数据隐私与安全**：作为本地工具，必须确保在启用本地模型（Ollama/LM-Studio）时，用户的核心源码绝不上传至任何外部服务器。
*   **性能要求**：AST 解析与 Tree-sitter 提取需在毫秒级完成；大型项目的 AI 分析需支持流式输出（Streaming），避免界面卡顿。
*   **扩展性**：预留标准接口，方便后续接入其他图表库（如 Draw.io 嵌入）或新的 AI 推理框架。

###  五、推荐系统模块划分

| 模块名称 | 技术栈/工具 | 核心职责 |
| :--- | :--- | :--- |
| **GUI 交互层** | Electron + Vue 3 | 界面渲染、文件管理、图表交互、动画控制面板 |
| **可视化渲染层** | Mermaid, PlantUML, D3.js | 渲染静态架构图、执行自定义教学动画逻辑 |
| **分析调度层** | Python (Backend) | 协调 AST 插件与 AI 接口，处理分析任务队列 |
| **代码解析层** | Python + Tree-sitter | 高精度提取源码语法树、符号引用与依赖关系 |
| **AI 适配层** | Ollama, LM-Studio, OpenAI API | 统一大模型调用接口，处理 Prompt 与上下文管理 |

这份需求分析涵盖了从底层解析到前端展示的完整链路。如果您需要针对“D3教学动画引擎”的具体交互设计，或者 Python 与 Electron 的通信方案（如 IPC 或本地 HTTP 服务）进行更深入的探讨，随时可以告诉我！

# 多语言解析器重构方案

**版本**: v1.0 (草案)
**日期**: 2026-05-18
**触发原因**: Java AST 解析诊断发现系统性问题，需统一修复所有语言

---

## 1. 现状问题总结

### 1.1 架构层问题

| 问题 | 严重度 | 影响范围 |
|------|--------|----------|
| **三套独立注册系统** | 高 | LanguageRegistry / CallGraphExtractorRegistry / DependencyExtractorRegistry 各自为政 |
| **语言处理器与提取器双层委托** | 高 | `JavaLanguageProcessor` → `JavaCallGraphExtractor` → `JavaCallExtractor`，三层嵌套 |
| **硬编码语言分流** | 中 | `extract_call_graph.py` 中 `if language in ['java', 'javascript', 'typescript']` 违反开闭原则 |
| **全局 `db` 变量污染** | 中 | 所有语言处理器直接引用全局 MongoDB 变量，无法单元测试 |
| **两套并行抽象基类** | 低 | `call_parser/base.py` 和 `extractor_factory.py` 各定义了一个 `CallGraphExtractor` |

### 1.2 数据质量缺陷

| 缺陷 | Java | C/C++ | Python | Go | JS/TS | 根因 |
|------|------|-------|--------|----|-------|------|
| **依赖路径截断** | ✅ | ✅ | ✅ | ✅ | ✅ | `_extract_dependency_target` 只取 `refs[0]` |
| **调用解析率低** | 55.6% | 未知 | 未知 | 未知 | 未知 | 方法映射缺少类/命名空间上下文 |
| **方法签名不完整** | ✅ | ✅ | ✅ | ✅ | ✅ | 只记录名称，无参数类型 |
| **同名方法覆盖** | ✅ | ✅ | ✅ | ✅ | ✅ | `method_map[name]` 单值覆盖 |
| **系统库未标记** | 部分 | 部分 | 部分 | 部分 | 部分 | 各语言标准库列表不完整 |

### 1.3 配置层问题

| 问题 | 影响语言 |
|------|----------|
| C++/TS 缺少 `name_extract_rules` | C++, TypeScript |
| C 语言 `NODE_TYPE_TO_OP` 重复键覆盖 | C |
| TS 配置未真正继承 JS (手动子集) | TypeScript |
| 12 种 AST 配置 vs 7 种语言处理器不匹配 | Swift, PHP, C#, Rust 有配置无处理器 |

## 2. 重构目标

```
┌─────────────────────────────────────────────────────────────────┐
│  目标 1: 语言隔离 — 修改 Java 不影响 Python                     │
│  目标 2: 统一入口 — 一个注册中心管理所有语言插件                 │
│  目标 3: 质量可测 — 每次分析输出评估报告                          │
│  目标 4: 跨语言可扩展 — 预留 FFI/多语言项目支持                   │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 目标架构

### 3.1 核心设计原则

```
┌──────────────────────────────────────────────────────────────┐
│                     LanguagePluginRegistry                    │
│                   (统一注册中心, 单例)                         │
│                                                              │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐       │
│  │  JavaPlugin  │  │ PythonPlugin │  │  GoPlugin    │  ...  │
│  │              │  │              │  │              │       │
│  │ - config     │  │ - config     │  │ - config     │       │
│  │ - ast_parser │  │ - ast_parser │  │ - ast_parser │       │
│  │ - symbol     │  │ - symbol     │  │ - symbol     │       │
│  │ - call_graph │  │ - call_graph │  │ - call_graph │       │
│  │ - dependency │  │ - dependency │  │ - dependency │       │
│  │ - metrics    │  │ - metrics    │  │ - metrics    │       │
│  └──────────────┘  └──────────────┘  └──────────────┘       │
└──────────────────────────────────────────────────────────────┘
```

**关键变化**:
- 从 **3 个注册表 + 双层委托** → **1 个注册表 + 单层插件**
- 每个语言插件自包含：配置 + AST 解析 + 符号 + 调用图 + 依赖图 + 质量评估
- 新增语言只需实现 `LanguagePlugin` 协议并注册，无需修改调度器

## 4. LanguagePlugin 协议定义

```python
# backend/parsers/plugin.py
"""
语言插件协议 — 所有语言必须实现的统一接口

设计原则:
- 每个插件自包含，不依赖其他语言插件
- 插件内部可自由调整策略，不影响外部调用
- 通过协议约束行为，通过配置字典控制节点类型
"""
from abc import ABC, abstractmethod
from typing import Dict, Any, List, Optional, Protocol, runtime_checkable
from dataclasses import dataclass


@dataclass
class LanguageMeta:
    """语言元数据"""
    name: str                          # 语言名: java, python, go
    file_extensions: List[str]         # ['.java'], ['.py', '.pyw']
    priority: int = 0                  # 扩展名冲突时的优先级
    tree_sitter_lang: str = ""         # tree-sitter 语言包名
    description: str = ""


@dataclass
class NodeConfig:
    """节点类型配置 — 替代分散在 code_parser/ 的 lang_*.py"""
    important_types: set               # 需要保留的 AST 节点类型
    name_node_types: set               # 名称节点 (identifier, type_identifier)
    scope_creating_types: set          # 创建作用域的节点
    defining_context_types: set        # 定义符号的上下文节点
    call_expression_types: set         # 调用表达式节点
    dependency_node_types: set         # 依赖节点 (import/include)
    function_def_types: set            # 函数/方法定义节点
    class_def_types: set               # 类/接口定义节点
    node_type_to_op: Dict[str, str]    # 节点类型 → 操作类型映射
    name_extract_rules: Dict[str, List[str]]  # 节点类型 → 名称提取子节点路径


@dataclass
class CallEdge:
    """调用边 — 统一输出格式"""
    caller_file_id: str
    caller_func_name: str             # 格式: "ClassName.methodName" 或 "methodName"
    caller_node_id: str
    callee_name: str                  # 格式: "ClassName.methodName" 或 "methodName"
    callee_file_id: Optional[str] = None
    callee_node_id: Optional[str] = None
    callee_type: str = "method"       # method/constructor/function/macro/builtin/external
    call_type: str = "direct"         # direct/method/constructor/static/builtin/external
    confidence: float = 1.0           # 解析置信度 0.0-1.0
    is_cross_language: bool = False   # 是否跨语言调用
    target_language: Optional[str] = None


@dataclass
class DepEdge:
    """依赖边 — 统一输出格式"""
    source_file_id: str
    target_path: str                  # 完整路径: "org.springframework.beans.BeansException"
    target_file_id: Optional[str] = None
    is_system: bool = True
    dep_type: str = "import"          # import/include/require/mod
    is_static: bool = False
    is_wildcard: bool = False
    confidence: float = 1.0


@dataclass
class Symbol:
    """符号 — 统一输出格式"""
    file_id: str
    node_id: str
    symbol_type: str                  # class/interface/enum/method/constructor/field/function/macro
    name: str                         # 完整名称: "com.example.MyClass" 或 "MyClass"
    short_name: str                   # 简短名称: "MyClass"
    scope: str = "global"             # global/class/method/local
    is_static: bool = False
    parameters: Optional[str] = None  # JSON: 参数类型列表
    return_type: Optional[str] = None
    start_line: int = 0
    end_line: int = 0


@runtime_checkable
class LanguagePlugin(Protocol):
    """
    语言插件协议

    实现此协议的语言插件可以独立开发、测试、注册。
    修改一个语言的实现不会影响其他语言。
    """

    @property
    @abstractmethod
    def meta(self) -> LanguageMeta:
        """语言元数据"""
        ...

    @property
    @abstractmethod
    def config(self) -> NodeConfig:
        """节点类型配置"""
        ...

    @abstractmethod
    def extract_symbols(
        self,
        nodes_by_file: Dict[str, Dict[str, Dict]],
    ) -> List[Symbol]:
        """
        提取符号

        Args:
            nodes_by_file: {file_id: {node_id: node_dict}}

        Returns:
            符号列表
        """
        ...

    @abstractmethod
    def extract_call_graph(
        self,
        nodes_by_file: Dict[str, Dict[str, Dict]],
        all_symbols: List[Symbol],  # 全局符号表，用于解析 callee
    ) -> List[CallEdge]:
        """
        提取调用图

        Args:
            nodes_by_file: 当前语言的 AST 节点
            all_symbols: 全局符号表 (包含所有语言的符号)

        Returns:
            调用边列表
        """
        ...

    @abstractmethod
    def extract_dependencies(
        self,
        nodes_by_file: Dict[str, Dict[str, Dict]],
        project_file_paths: set,    # 项目文件路径集合，用于判断内部/外部依赖
    ) -> List[DepEdge]:
        """
        提取依赖图

        Args:
            nodes_by_file: 当前语言的 AST 节点
            project_file_paths: 项目文件路径集合

        Returns:
            依赖边列表
        """
        ...

    @abstractmethod
    def is_system_symbol(self, symbol_name: str) -> bool:
        """判断是否为系统/标准库符号"""
        ...

    def get_cross_language_interfaces(self) -> List[Dict[str, str]]:
        """
        获取可能被其他语言调用的接口 (可选实现)

        用于跨语言调用分析，例如:
        - Java 的 JNI 方法
        - Python 的 ctypes/CFFI
        - Go 的 cgo
        - JS 的 native 模块

        Returns:
            [{"language": "c", "symbol": "Java_com_example_MyClass_method", ...}]
        """
        return []
```

## 5. 统一注册中心

```python
# backend/parsers/registry.py
"""
统一语言插件注册中心

替代原有的:
- LanguageRegistry (languages/language_registry.py)
- CallGraphExtractorRegistry (call_parser/extractor_factory.py)
- DependencyExtractorRegistry (dependence_parser/extractor_factory.py)

使用方式:
    from parsers.registry import LanguageRegistry

    # 注册
    LanguageRegistry.register(JavaPlugin())

    # 获取
    plugin = LanguageRegistry.get('java')
    symbols = plugin.extract_symbols(nodes_by_file)
    calls = plugin.extract_call_graph(nodes_by_file, all_symbols)
    deps = plugin.extract_dependencies(nodes_by_file, file_paths)

    # 按扩展名路由
    plugin = LanguageRegistry.get_by_extension('.java')
"""
from typing import Dict, List, Optional, Type
from .plugin import LanguagePlugin, LanguageMeta


class LanguageRegistry:
    _instance = None
    _plugins: Dict[str, LanguagePlugin] = {}
    _extension_map: Dict[str, str] = {}  # extension -> language_name

    @classmethod
    def register(cls, plugin: LanguagePlugin):
        """注册语言插件"""
        meta = plugin.meta
        cls._plugins[meta.name] = plugin
        for ext in meta.file_extensions:
            # 高优先级覆盖低优先级
            if ext not in cls._extension_map or \
               cls._plugins.get(cls._extension_map[ext], {}).meta.priority < meta.priority:
                cls._extension_map[ext] = meta.name

    @classmethod
    def get(cls, language: str) -> Optional[LanguagePlugin]:
        return cls._plugins.get(language)

    @classmethod
    def get_by_extension(cls, extension: str) -> Optional[LanguagePlugin]:
        lang = cls._extension_map.get(extension)
        return cls._plugins.get(lang) if lang else None

    @classmethod
    def list_languages(cls) -> List[str]:
        return list(cls._plugins.keys())

    @classmethod
    def auto_discover(cls):
        """自动发现并注册所有语言插件 (导入 languages/*/__init__.py)"""
        import importlib
        import pkgutil
        import parsers.languages as languages_pkg

        for importer, modname, ispkg in pkgutil.iter_modules(languages_pkg.__path__):
            if ispkg and not modname.startswith('_'):
                try:
                    importlib.import_module(f'parsers.languages.{modname}')
                except ImportError:
                    pass
```

## 6. 分析质量评估体系

### 6.1 评估维度

```python
# backend/parsers/metrics.py
"""
分析质量评估体系

每次分析任务完成后，自动计算以下指标并写入分析报告。
用于:
1. 评估单次分析是否全面
2. 对比不同版本的解析器改进效果
3. 识别需要人工检查的边界情况
"""
from dataclasses import dataclass, field
from typing import Dict, List, Optional
from enum import Enum


class MetricLevel(Enum):
    """指标级别"""
    INFO = "info"         # 信息性
    WARNING = "warning"   # 需要关注
    ERROR = "error"       # 可能遗漏


@dataclass
class CallGraphMetrics:
    """调用图质量指标"""

    # === 基础统计 ===
    total_call_expressions: int = 0           # AST 中的调用表达式总数
    extracted_edges: int = 0                  # 提取的调用边数
    resolved_edges: int = 0                   # 解析到 callee 定义的边数
    unresolved_edges: int = 0                 # 未解析的边数

    # === 解析率 ===
    resolution_rate: float = 0.0              # resolved / total (目标 >80%)

    # === 分类统计 ===
    by_callee_type: Dict[str, int] = field(default_factory=dict)
    # {"method": 1000, "constructor": 100, "builtin": 50, "external": 200}

    # === 置信度分布 ===
    high_confidence: int = 0                  # confidence >= 0.8
    medium_confidence: int = 0                # 0.5 <= confidence < 0.8
    low_confidence: int = 0                   # confidence < 0.5

    # === 问题诊断 ===
    unresolved_top_callees: List[Dict[str, Any]] = field(default_factory=list)
    # [{"name": "isEqualTo", "count": 68, "likely_reason": "external_library"}]

    unresolved_reasons: Dict[str, int] = field(default_factory=dict)
    # {"external_library": 200, "overload_ambiguous": 50, "dynamic_dispatch": 30}


@dataclass
class DependencyGraphMetrics:
    """依赖图质量指标"""

    total_import_statements: int = 0          # AST 中的 import 语句总数
    extracted_edges: int = 0                  # 提取的依赖边数
    resolved_to_file: int = 0                 # 解析到具体文件的边数
    system_deps: int = 0                      # 系统库依赖数
    internal_deps: int = 0                    # 项目内部依赖数
    external_deps: int = 0                    # 外部第三方库依赖数

    # === 路径完整性 ===
    complete_paths: int = 0                   # 完整路径 (org.springframework.beans.X)
    truncated_paths: int = 0                  # 截断路径 (org) ← Bug 指标

    # === 问题诊断 ===
    wildcard_imports: int = 0                 # 通配符导入 (无法精确定位)
    unresolved_imports: List[str] = field(default_factory=list)


@dataclass
class SymbolMetrics:
    """符号提取质量指标"""

    total_symbols: int = 0
    by_type: Dict[str, int] = field(default_factory=dict)
    # {"class": 100, "method": 500, "field": 200, ...}

    # === 覆盖度 ===
    files_with_symbols: int = 0               # 包含符号的文件数
    files_without_symbols: int = 0            # 无符号的文件数 (可能是测试/配置)

    # === 完整性 ===
    methods_with_params: int = 0              # 带参数类型的方法数
    methods_without_params: int = 0           # 缺失参数类型的方法数
    classes_with_hierarchy: int = 0           # 有继承关系的类数
    classes_without_hierarchy: int = 0        # 无继承信息的类数


@dataclass
class AnalysisQualityReport:
    """
    分析质量报告 — 每次分析任务生成一份

    写入 analysis_reports 表的 quality_metrics 字段 (JSON)
    """

    task_id: str
    language: str

    # === 子指标 ===
    symbols: SymbolMetrics = field(default_factory=SymbolMetrics)
    call_graph: CallGraphMetrics = field(default_factory=CallGraphMetrics)
    dependency_graph: DependencyGraphMetrics = field(default_factory=DependencyGraphMetrics)

    # === 综合评分 ===
    overall_score: float = 0.0                # 0-100
    call_graph_score: float = 0.0             # 0-100
    dependency_score: float = 0.0             # 0-100
    symbol_coverage_score: float = 0.0        # 0-100

    # === 诊断建议 ===
    warnings: List[str] = field(default_factory=list)
    suggestions: List[str] = field(default_factory=list)

    def to_dict(self) -> Dict:
        """序列化为 JSON 可存储格式"""
        return {
            "task_id": self.task_id,
            "language": self.language,
            "overall_score": self.overall_score,
            "call_graph": {
                "resolution_rate": self.call_graph.resolution_rate,
                "resolved": self.call_graph.resolved_edges,
                "unresolved": self.call_graph.unresolved_edges,
                "unresolved_top_callees": self.call_graph.unresolved_top_callees[:10],
            },
            "dependency_graph": {
                "complete_paths": self.dependency_graph.complete_paths,
                "truncated_paths": self.dependency_graph.truncated_paths,
                "system_deps": self.dependency_graph.system_deps,
                "internal_deps": self.dependency_graph.internal_deps,
            },
            "symbols": {
                "total": self.symbols.total_symbols,
                "by_type": self.symbols.by_type,
            },
            "warnings": self.warnings,
            "suggestions": self.suggestions,
        }


def compute_quality_report(
    language: str,
    symbols: List[Symbol],
    call_edges: List[CallEdge],
    dep_edges: List[DepEdge],
    total_files: int,
    total_call_expressions: int,
    total_import_statements: int,
) -> AnalysisQualityReport:
    """
    计算分析质量报告

    评分算法:
    - call_graph_score: resolution_rate * 60 + (1 - truncated_ratio) * 40
    - dependency_score: (1 - truncated_ratio) * 70 + resolved_ratio * 30
    - symbol_coverage_score: files_with_symbols / total_files * 100
    - overall_score: 0.4 * call + 0.3 * dep + 0.3 * symbol
    """
    report = AnalysisQualityReport(task_id="", language=language)

    # --- 符号指标 ---
    report.symbols.total_symbols = len(symbols)
    by_type: Dict[str, int] = {}
    for s in symbols:
        by_type[s.symbol_type] = by_type.get(s.symbol_type, 0) + 1
    report.symbols.by_type = by_type

    # --- 调用图指标 ---
    report.call_graph.total_call_expressions = total_call_expressions
    report.call_graph.extracted_edges = len(call_edges)
    report.call_graph.resolved_edges = sum(1 for e in call_edges if e.callee_file_id)
    report.call_graph.unresolved_edges = sum(1 for e in call_edges if not e.callee_file_id)
    if call_edges:
        report.call_graph.resolution_rate = report.call_graph.resolved_edges / len(call_edges)

    # 置信度分布
    for e in call_edges:
        if e.confidence >= 0.8:
            report.call_graph.high_confidence += 1
        elif e.confidence >= 0.5:
            report.call_graph.medium_confidence += 1
        else:
            report.call_graph.low_confidence += 1

    # 按类型分类
    by_callee_type: Dict[str, int] = {}
    for e in call_edges:
        by_callee_type[e.callee_type] = by_callee_type.get(e.callee_type, 0) + 1
    report.call_graph.by_callee_type = by_callee_type

    # 未解析 Top callees
    unresolved_count: Dict[str, int] = {}
    for e in call_edges:
        if not e.callee_file_id:
            unresolved_count[e.callee_name] = unresolved_count.get(e.callee_name, 0) + 1
    report.call_graph.unresolved_top_callees = sorted(
        [{"name": k, "count": v} for k, v in unresolved_count.items()],
        key=lambda x: x["count"], reverse=True
    )[:10]

    # --- 依赖图指标 ---
    report.dependency_graph.total_import_statements = total_import_statements
    report.dependency_graph.extracted_edges = len(dep_edges)
    report.dependency_graph.system_deps = sum(1 for e in dep_edges if e.is_system)
    report.dependency_graph.internal_deps = sum(1 for e in dep_edges if not e.is_system and e.target_file_id)
    report.dependency_graph.external_deps = sum(1 for e in dep_edges if not e.is_system and not e.target_file_id)

    # 路径完整性检查
    for e in dep_edges:
        if '.' in e.target_path:
            report.dependency_graph.complete_paths += 1
        else:
            report.dependency_graph.truncated_paths += 1

    # --- 综合评分 ---
    if call_edges:
        report.call_graph_score = report.call_graph.resolution_rate * 100
    else:
        report.call_graph_score = 100.0  # 无调用 = 完美

    if dep_edges:
        path_quality = report.dependency_graph.complete_paths / len(dep_edges)
        report.dependency_score = path_quality * 100
    else:
        report.dependency_score = 100.0

    report.symbol_coverage_score = min(100.0, len(symbols) / max(total_files, 1) * 100 / 10)

    report.overall_score = (
        0.4 * report.call_graph_score +
        0.3 * report.dependency_score +
        0.3 * report.symbol_coverage_score
    )

    # --- 诊断建议 ---
    if report.call_graph.resolution_rate < 0.5:
        report.warnings.append(f"调用解析率仅 {report.call_graph.resolution_rate:.1%}，低于 50% 阈值")
    if report.dependency_graph.truncated_paths > 0:
        report.warnings.append(f"{report.dependency_graph.truncated_paths} 条依赖路径被截断，需修复 _extract_dependency_target")
        report.suggestions.append("检查依赖提取器是否正确拼接 refs 数组")
    if report.call_graph.low_confidence > len(call_edges) * 0.2:
        report.warnings.append(f"低置信度调用边占比过高 ({report.call_graph.low_confidence}/{len(call_edges)})")

    return report
```

## 7. 跨语言调用扩展机制

```python
# backend/parsers/cross_language.py
"""
跨语言调用扩展接口

支持场景:
1. Java → C (JNI)
2. Python → C (ctypes/CFFI)
3. Go → C (cgo)
4. Node.js → C++ (native addon)
5. TypeScript → JavaScript (混合项目)

设计原则:
- 各语言插件独立声明自己的"对外接口"
- 跨语言调度器收集所有接口，构建跨语言调用图
- 不影响单语言分析的独立性
"""
from typing import Dict, List, Optional, Protocol
from dataclasses import dataclass


@dataclass
class CrossLanguageInterface:
    """跨语言接口声明"""
    source_language: str           # 声明方语言: "java"
    target_language: str           # 目标语言: "c"
    bridge_type: str               # 桥接机制: "jni", "ctypes", "cgo", "native_addon"
    source_symbol: str             # 源语言符号: "com.example.MyClass.nativeMethod"
    target_symbol: str             # 目标语言符号: "Java_com_example_MyClass_nativeMethod"
    source_file_id: Optional[str] = None
    is_export: bool = True         # True=导出(被调用), False=导入(调用方)


class CrossLanguageBridge(Protocol):
    """
    跨语言桥接器协议

    实现此协议可以添加新的跨语言桥接机制。
    """

    @property
    def bridge_type(self) -> str:
        """桥接类型: jni, ctypes, cgo, native_addon"""
        ...

    @property
    def supported_language_pairs(self) -> List[tuple]:
        """支持的语言对: [("java", "c"), ("java", "cpp")]"""
        ...

    def discover_interfaces(
        self,
        nodes_by_file: Dict[str, Dict[str, Dict]],
        source_language: str,
    ) -> List[CrossLanguageInterface]:
        """
        发现跨语言接口

        例如 JNI 桥接器扫描 Java 代码中的 native 方法声明，
        生成对应的 C 函数名映射。
        """
        ...

    def resolve_cross_language_call(
        self,
        source_symbol: str,
        all_interfaces: List[CrossLanguageInterface],
    ) -> Optional[CrossLanguageInterface]:
        """解析跨语言调用目标"""
        ...


# 注册表
_bridge_registry: Dict[str, CrossLanguageBridge] = {}


def register_bridge(bridge: CrossLanguageBridge):
    """注册跨语言桥接器"""
    _bridge_registry[bridge.bridge_type] = bridge


def get_bridge(bridge_type: str) -> Optional[CrossLanguageBridge]:
    return _bridge_registry.get(bridge_type)


def discover_all_cross_language_interfaces(
    plugins_by_language: Dict[str, 'LanguagePlugin'],
    nodes_by_file: Dict[str, Dict[str, Dict]],
) -> List[CrossLanguageInterface]:
    """
    发现所有跨语言接口

    流程:
    1. 遍历所有已注册的桥接器
    2. 对每个桥接器支持的语言对，调用 discover_interfaces
    3. 合并结果
    """
    all_interfaces: List[CrossLanguageInterface] = []

    for bridge in _bridge_registry.values():
        for src_lang, tgt_lang in bridge.supported_language_pairs:
            if src_lang in plugins_by_language:
                plugin = plugins_by_language[src_lang]
                interfaces = bridge.discover_interfaces(
                    nodes_by_file.get(src_lang, {}),
                    src_lang,
                )
                all_interfaces.extend(interfaces)

    return all_interfaces
```

### 7.1 JNI 桥接器示例

```python
# backend/parsers/cross_language_bridges/jni.py
"""
Java → C/C++ JNI 桥接器

扫描 Java 代码中的 native 方法声明，生成 C 函数名映射。

Java:  public native void myMethod(int x);
C:     Java_PackageClass_myMethod(JNIEnv* env, jobject obj, jint x)
"""
from ..cross_language import CrossLanguageBridge, CrossLanguageInterface


class JNIBridge(CrossLanguageBridge):
    @property
    def bridge_type(self) -> str:
        return "jni"

    @property
    def supported_language_pairs(self) -> list:
        return [("java", "c"), ("java", "cpp")]

    def discover_interfaces(self, nodes_by_file, source_language):
        interfaces = []
        for file_id, nodes in nodes_by_file.items():
            for node in nodes.values():
                if node.get("type") == "method_declaration":
                    # 检查是否有 native 修饰符
                    modifiers = self._get_modifiers(node, nodes)
                    if "native" in modifiers:
                        method_name = node.get("name")
                        class_name = self._find_enclosing_class(node, nodes)
                        if method_name and class_name:
                            # 生成 C 函数名
                            c_name = self._jni_mangle(class_name, method_name)
                            interfaces.append(CrossLanguageInterface(
                                source_language="java",
                                target_language="c",
                                bridge_type="jni",
                                source_symbol=f"{class_name}.{method_name}",
                                target_symbol=c_name,
                                source_file_id=file_id,
                            ))
        return interfaces

    def _jni_mangle(self, class_name: str, method_name: str) -> str:
        """生成 JNI 函数名: Java_com_example_MyClass_methodName"""
        parts = class_name.replace('.', '_')
        return f"Java_{parts}_{method_name}"
```

## 二、后端 API 新增

### 2.1 `getCrossCommunityEdges`

```
IPC: analysis.getCrossCommunityEdges
TypeScript: ipc.ts (新增)
Backend: task_manager.py (新增方法)

输入: { taskId, edgeType, commLv }
输出: { crossEdges: [{ sourceCommId, targetCommId, edgeCount }] }
```

**实现逻辑**（task_manager.py 新增）:
1. `analysis_store.get_graph_edges(task_id, kind)` → 全量边
2. 遍历 `graph_doc WHERE task_id=? AND edge_type=? AND comm_lv=?` → 解析每个社区的 `node_list` JSON，构建 `node_id → comm_id` 反向索引
3. 遍历全量边，查反向索引得 `source_comm` 和 `target_comm`，`source_comm ≠ target_comm` → 跨社区边
4. `GROUP BY (source_comm, target_comm)`，COUNT 聚合
5. 返回聚合结果

### 2.2 `getExternalStats` 扩展

```
现有输出增加字段:

ExternalDepItem:
  package: string
  fileCount: number
  files: string[]
+ communities: Array<{ communityId: string, name?: string }>  // 新增

ExternalCallItem:
  name: string
  count: number
  files: string[]
+ communities: Array<{ communityId: string, name?: string }>  // 新增
```

**实现逻辑**: 对每个外部包/API 的 `files[]` 中的每个文件，查该文件所属的 L0 社区（通过 `graph_doc` 或 `community_hierarchy`），去重聚合。

## 五、各功能点详细设计

### 5.1 Tag 视图增强

```
CommunityTagView
├─ 层级过滤器    → <select> L0 | L1 | ... | L5（仅现存层级）
│                  默认 L0，onChange 切换显示层级
├─ 分页          → 动态 pageSize (50-200)，基于容器高度
│                  pageSize = Math.floor(viewportHeight / 28)
│                  clamp 50-200
└─ 搜索          → 复用 communitySearch，过滤 commName/communityId
```

### 5.2 Graph 视图钻取

```
状态: currentViewKey = 'L0'                       // 初始
状态: breadcrumbPath = [{ key:'L0', label:'全部' }]

双击社区节点:
  → currentViewKey = `comm-${communityId}`
  → breadcrumbPath.push({ key, label: commName })
  → 加载该社区的 L+1 子节点 + 子节点间的跨社区边
  → GraphCanvas 重新渲染

点击面包屑/返回按钮:
  → currentViewKey = 上一级 key
  → breadcrumbPath.pop()
  → 加载上一级数据
  → GraphCanvas 重新渲染

点击面包屑某一级:
  → 截断到该级，重新加载
```

### 5.3 两种渲染风格

```
GraphCanvas 内部:
  if (style === 'd3force') → D3ForceRenderer.render(svg, nodes, edges)
  if (style === 'dagre')   → DagreRenderer.render(svg, nodes, edges)

共用:
  - SVG 容器
  - 拖拽事件 (D3 drag behavior)
  - 缩放/平移 (D3 zoom behavior)
  - 节点点击/双击事件
  - 位置持久化读写
```

**D3ForceRenderer** (复用现有 `useD3Graph`):
- 力模拟 → 节点自由分布
- 边: 贝塞尔曲线偏移 (控制点偏移避障)
- 边层在节点层之下 (z-order)

**DagreRenderer** (新增):
- `dagre.layout(g)` → 节点分配层级 + 层内坐标
- 边: dagre 内置正交路由 (折线路径)
- 节点按层级从左到右/从上到下排列
- 布局结果稳定 (无物理模拟)

### 5.4 全屏模式

```
状态: isFullscreen (provide/inject 或 panelStore)

GraphToolbar 全屏按钮:
  → panelStore.setFullscreen(true)
  → AppShell: v-show="!isFullscreen" 隐藏 TopBar/ActivityBar/StatusBar
  → LeftPanel: 强制折叠, fullscreenLockLeft 禁止展开
  → RightPanel: 折叠, 可手动展开
  → GraphCanvas: position:fixed; inset:0; z-index:200

退出全屏:
  → 工具栏按钮 / ESC 键
  → panelStore.setFullscreen(false)
  → 恢复各组件可见性

从 graph 节点呼出右面板:
  → 右键菜单 "AI 对话" → setRightCollapsed(false) + setRightTab('ai')
  → 预填节点名称/ID 到 AI 对话框上下文
```

### 5.5 位置持久化

```
useGraphPosition(projectId, taskId, taskUpdatedAt)

存储:
  key: `graph-pos-${projectId}-${taskId}`
  value: {
    v: 1,                          // schema 版本
    taskAt: taskUpdatedAt,
    positions: {
      [edgeType]: {
        [viewKey]: {
          [nodeId]: { x, y, fx?, fy? }
        }
      }
    }
  }

加载:
  if (stored.taskAt !== currentTaskUpdatedAt) → 清除, 自动布局
  else → 应用存储位置

保存:
  防抖 300ms, node-drag-end 时写入
```

### 5.6 >100 节点合并

```
threshold = 100

displayNodes = allNodes
  .sort((a,b) => b.nodeCount - a.nodeCount)
  .slice(0, threshold)

mergedNode = {
  id: '__merged__',
  label: `其他 ${allNodes.length - threshold} 个社区`,
  nodeCount: sum(remaining.nodeCount),
}

点击 mergedNode 展开:
  → 第一批: 50 个节点加入画布
  → 如仍有剩余, 再次点击 → 询问 "是否全量展开({n}个节点)？"
  → 确认 → 全部加入, mergedNode 消失
```

### 5.7 外部标签页 Graph 模式

```
数据: externalStats.externalDeps[].communities  (后端新增字段)

渲染:
  根节点: 外部包名 (package/API name)
  叶子节点: 引用该包的 L0 社区 (按 communities 字段)
  边: 根节点 → 每个社区节点

交互:
  社区节点可双击钻取 (进入正常 INCLUDE graph 的钻取流程)
  外部包节点不可展开
  风格切换同样适用
```

## 六、版本管理拓展点

为后续「架构修改轨迹跟踪」预留：

```
GraphPositionStore 预留字段:
  versions: Array<{
    id: string
    createdAt: string
    taskId: string
    positions: ...     // 该版本的节点位置快照
  }>
```

- 当前仅存储最新版本位置
- `v` schema 版本号支持后续结构升级
- `versions[]` 数组预留历史快照存储结构
- 后续可开发版本对比视图 (diff 两个版本的布局变化)

## 八、风险与注意事项

| 风险 | 缓解措施 |
|------|----------|
| dagre 布局对大量节点(>500)的边路由性能 | 已在 Phase 4 设 >100 合并阈值，dagre 在 <500 节点表现良好 |
| 跨社区边后端性能（全量边遍历） | 使用内存索引 + 单次遍历 O(E), 不返回单条边仅返回聚合 |
| D3Force vs Dagre 切换时位置存储冲突 | 分别存储位置 key: `d3force` / `dagre`, 切换时独立恢复 |
| 全屏模式与 AppShell 现有 hideLeftPanel 逻辑冲突 | 新增 `isFullscreen` 状态独立管理，不影响现有逻辑 |
| ReportHome 重构导致现有功能回归 | Phase 2 完成后先验证 tag 模式完全不变, 再进入 Phase 3 |

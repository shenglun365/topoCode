## 二、5 个业务流程完整数据流

### 流程 1：项目导入

```
ImportZone.vue
  └─ doImport(path: string)
       └─ projectStore.importProject(path)
            └─ ipc.project.import(path)
                 └─ api.project.import(path)  ← preload 桥接
                      └─ ZeroMQ → backend project.import(path)
                           ├─ _scan_file_tree() → 写入项目库 source_files
                           ├─ main_db.insert("projects", {...})
                           └─ main_db.fetchone("SELECT * FROM projects WHERE id = ?")
                      ← 返回 Project (snake_case)
                 ← adaptProject() 转换 snake→camel
            ← 再次字段适配（冗余）
       ← 返回 Project (camelCase)
       └─ projectStore.loadProjects() 刷新列表
```

**数据字段映射：**

| 后端返回 (snake_case) | ipc.ts adaptProject | 前端使用 (camelCase) |
|---|---|---|
| root_path | → rootPath | rootPath |
| file_count | → fileCount | fileCount |
| needs_resync | → needsResync | needsResync |
| has_file_changes | → hasFileChanges | hasFileChanges |
| is_sample | → isSample | isSample |
| last_sync | → lastSync | lastSync |
| created_at | → createdAt | createdAt |

**日志点：** 无（后端无 print/logger，前端无 console.log）

**问题：**
- ⚠️ 双重字段适配：`ipc.ts` 的 `adaptProject()` 和 `project.ts` 的 `importProject()` 都做 snake→camel 转换，store 层是冗余的
- ⚠️ 后端 `project.import` 无任何日志输出，排查困难

### 流程 3：任务新建

```
TaskCreateForm.vue (新建模式)
  └─ handleSubmit()
       ├─ console.log: [TaskCreateForm] handleSubmit: ...
       ├─ const taskParams = {
       │     projectId,
       │     type: 'full',
       │     name,
       │     scopes: selectedScopes.value,    ← 数组! 但 TS 签名声明 scope?: string
       │     extensions: extArray,
       │     excludeDirs: excludeArray,

       │   }
       └─ analysisStore.createTask(taskParams)
            ├─ console.log: === [AnalysisStore] createTask called ===
            ├─ console.log: [AnalysisStore] createTask params: ${JSON.stringify(params, null, 2)}
            ├─ console.log: [AnalysisStore] createTask: calling ipc.analysis.createTask...

                 ├─ console.log: [IPC] createTask -> api.analysis.createTask: ${JSON.stringify(params)}
                 └─ api.analysis.createTask(params)  ← preload
                      ├─ console.log: [Preload] createTask called: ${JSON.stringify(params)}
                      └─ ZeroMQ → backend analysis.createTask(params)
                           ├─ 接收 params: {projectId, type, name, scopes?, extensions?, excludeDirs?, reportTypes?}
                           ├─ 字段映射: excludeDirs→exclude_dirs, reportTypes→report_types
                           ├─ 序列化: extensions, exclude_dirs, report_types → JSON.dumps
                           ├─ ⚠️ scopes 在 allowed 集合中但未被 field_map 处理（camelCase→snake_case）
                           ├─ main_db.insert("analysis_tasks", {...})

                      ← 返回 task (scopes 为 JSON 字符串)
                 ├─ console.log: [IPC] createTask result: ${JSON.stringify(result)}
            ├─ console.log: [AnalysisStore] createTask: ipc returned, task=...
            ├─ console.log: [AnalysisStore] createTask: pushing task to tasks array...
            ├─ console.log: [AnalysisStore] createTask: completed successfully
            └─ tasks.value.push(task)
       ├─ console.log: [TaskCreateForm] NEW TASK: createTask returned=...
       └─ emit('created', created.id)
```

**数据字段传递链：**

| 字段 | 前端发送 | preload | 后端接收 | 后端写入 DB | DB 列 |
|---|---|---|---|---|---|
| 项目ID | `projectId` | projectId | projectId/project_id (兼容) | project_id | project_id |
| 类型 | `type: 'full'` | type | type | type | type |
| 名称 | `name` | name | name | name | name |
| 目录范围 | `scopes: string[]` | scopes | scopes | scopes (JSON) | scopes ✅ |
| 文件后缀 | `extensions: string[]` | extensions | extensions | extensions (JSON) | extensions ✅ |
| 排除目录 | `excludeDirs: string[]` | excludeDirs | exclude_dirs (映射) | exclude_dirs (JSON) | exclude_dirs ✅ |
| 报告类型 | `reportTypes: string[]` | reportTypes | report_types (映射) | report_types (JSON) | report_types ✅ |

**日志点：** 前端 15+ 条 console.log，后端 0 条

**问题：**
- 🔴 **TS 签名不匹配**：`AnalysisStore.createTask()` 签名声明 `scope?: string`，但实际传入 `scopes?: string[]`
- 🔴 **IPCAPI 接口不匹配**：`IPCAPI.analysis.createTask` 声明 `scope?: string`，与实际 `scopes?: string[]` 不一致
- ⚠️ `scopes` 是 camelCase 但后端直接当 snake_case 用（碰巧 `scopes` 本身就是 snake_case 形式）
- ⚠️ 后端 `createTask` 无日志

## 四、数据交互协议标准化

### 4.1 前端 → 后端（请求方向）

| 字段 | 前端发送 | 后端接收 | 转换规则 |
|---|---|---|---|
| 项目ID | `projectId` | `projectId` 或 `project_id` | 后端兼容两种命名 |
| 任务ID | `taskId` | `taskId` 或 `task_id` | 后端兼容两种命名 |
| 排除目录 | `excludeDirs` | `exclude_dirs` | 后端 field_map 转换 |
| 报告类型 | `reportTypes` | `report_types` | 后端 field_map 转换 |
| 目录范围 | `scopes` | `scopes` | **无需转换**（已是 snake_case 形式） |
| 文件后缀 | `extensions` | `extensions` | **无需转换** |

### 4.2 后端 → 前端（响应方向）

| 字段 | DB 存储 | 后端返回 | 前端接收 | 转换规则 |
|---|---|---|---|---|
| 数组字段 | JSON 字符串 | JS 数组（已解析） | 直接使用 | `listTasks`/`getTask` 已做 JSON 解析 |
| 项目字段 | snake_case | snake_case | camelCase | `ipc.ts adaptProject()` 转换 |
| 时间字段 | `created_at` | `created_at` | `createdAt` | `adaptProject()` 转换 |

> ⚠️ 后端 `listTasks` 和 `getTask` 已对 `scopes, extensions, exclude_dirs, report_types, tags` 做 JSON 解析。但 `createTask` 的返回值走的是 `fetchone` 直出，**未经过 JSON 解析**——前端收到的 `scopes`/`extensions` 等可能是 JSON 字符串而非数组。

### 4.3 createTask 返回值问题

```python
# backend/core_service.py - createTask
main_db.insert("analysis_tasks", data)  # data 中 scopes 是 JSON 字符串
task = main_db.fetchone("SELECT * FROM analysis_tasks WHERE id = ?")
return task  # ← 直接返回，scopes 仍是 JSON 字符串！
```

前端 `TaskCreateForm` 在 `loadExistingTask` 中有防御性代码：
```ts
if (loaded.scopes) {
  const sc = Array.isArray(loaded.scopes) ? loaded.scopes : JSON.parse(loaded.scopes)
  selectedScopes.value = [...sc]
}
```

但 `createTask` 返回后直接 `push(task)` 到 store，**未经过 JSON 解析**，store 中的任务对象 `scopes` 字段可能是字符串。

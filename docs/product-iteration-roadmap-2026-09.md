## 0. 执行摘要

| 项 | 结论 |
|---|---|
| 战略决策 | 以 **architect 工程闭环为旗舰**（需求提案 → 概要设计 → mandate → Coding Agent → 单测验收），KB/语义资产降级为**地基与弹药库**而非独立主打面 |
| 用户排序 | **对外 Agent 生态用户 > 个人开发者 > 团队工程效能**（边际成本排序；团队方向以 G 提升的数据模型先行、多人场景后置） |
| 推进结构 | **Phase 1 地基**（测试安全网 + KB 口径统一 + C1 拍板）→ **Phase 2 闭环攻坚**（黄金路径 + G 提升 + agent-bus）→ **Phase 3 生态输出**（MCP 工具面 + 资源中心试点）；**L 组模型微调** Phase 2 末启动、Phase 3 成型 |
| 北极星指标 | **黄金路径完成率**（一条需求从提案走到单测验收的比例），辅以 MCP 外部调用量、分析首屏耗时 |
| 商业化 | 不启动；守住三条架构预留（本地数据主权 / 项目库-主库分层 / MCP 审计），对应四条候选路径 |
| 模型微调 | 新增 **L 组专项**（§6，Phase 2 末启动）：四级成本梯度（L 确定性 / **S 微调小模型** / M 大本地 / H 云端），管线自造血训练数据，微调模型经资源中心分发 |
| 工程纪律 | 所有任务过 CONV-04 G1~G8 门禁；B 类巨型模块拆分**必须**排在 A1 测试安全网之后 |

## 1. 战略评估

### 1.1 两条主线的现状与竞争

| 主线 | 载体 | 现状证据 | 判断 |
|---|---|---|---|
| A. 架构认知/学习 | workbench + docs + chat | 功能完备；KB 组件统一 Stage 0~4 已完成（typecheck 零错，6 项目四语言验证）；进入打磨期 | 降为地基：继续供数据、修口径，不加新表面 |
| B. 工程闭环 SE Agent | architect（+ runner/cline-sidecar + agent-bus） | 全仓最大子系统（后端 2.1 万行 / 36 张 arch_* 表 / 前端 14 页 53 组件）；近期 git 提交 100% 集中于此；测试全仓标杆（28 文件） | **旗舰**：投入主战场，但必须开始"收敛"而非继续加表 |

资源实际投向（architect）与 README 自我定位（"分析显微镜"）存在漂移。本次决策**确认漂移为正式战略**：产品叙事从"帮人理解架构"升级为"把架构认知编译为 Coding Agent 的约束协议"（plan-A 的"认知前额叶"定位），主线 A 成为旗舰的支撑层。

### 1.2 目标用户排序及理由

| 优先级 | 用户群 | 理由 | 服务面 |
|---|---|---|---|
| 1 | **对外 Agent 生态用户**（Cursor/Cline/opencode 等） | MCP(:3460) 与 arch.* 工具面已存在，KB/语义资产输出是**同一能力的边际出口**；反向验证"供上下文"腿的价值；获客漏斗 | MCP 工具面做厚（Phase 3） |
| 2 | **个人开发者/学习者** | 基本盘与口碑来源；本地模型体验、分析等待时间是生死线 | L 级零 LLM 推广、渐进式首屏（Phase 2/3 穿插） |
| 3 | **团队工程效能** | 价值最重但依赖最多（G 提升、多人协同、治理流程）；按"单机先跑通、多人后置"推进 | G 提升数据模型先行（Phase 2），多人场景后置 |

### 1.3 商业化定位

暂不启动投入，但路径要想清楚（见 §7）。现阶段的唯一要求是**不破坏三条架构预留**：本地数据主权（隐私承诺是产品信用底线）、项目库/主库分离（天然切出免费/付费边界）、MCP 审计表（API 计费技术前提，`arch_mcp_calls` 已有）。

## 2. 阶段划分总览

```
Phase 1 地基期（~2-4 周）          Phase 2 闭环攻坚（1-2 月）              Phase 3 生态输出（随后）
├─ A1 测试安全网（四步）            ├─ 黄金路径 E2E 打磨 + 度量埋点          ├─ MCP 工具面做厚
├─ KB 统一 Stage 5 清理            ├─ G 提升（项目库→主库）落地             ├─ 资源中心试点
├─ C1 architect 半共享态拍板        ├─ cline-sidecar/runner 稳定性          ├─ 渐进式披露全管线推广
└─ A2/A3/A4 快赢顺手清              ├─ agent-bus 事件驱动化（D2）            └─（视验证结果）商业化路径 b 评估
                                   └─ architect 表面收敛（砍长尾）
```

依赖关系：**Phase 2 的所有重构类任务硬依赖 Phase 1 的 A1**（无安全网不拆巨石）；G 提升软依赖 KB Stage 5（统一口径的组件是提升对象之一）。

## 6. 本地小模型微调专项（L 组，Phase 2 末启动）

> 定位：把管线中**高频、模式化**的 LLM 任务下沉到本地微调小模型（候选底座：Qwen3.5-0.8B/2B/4B、MiniCPM5-1B/2B，均商用许可友好），构建四级成本梯度。
> 终局：**"TopoCode 认证的分析模型"成为资源中心可分发资产**——管线自造血训练数据（§6.4）是通用竞品难以复制的闭环；对照现状（README 推荐 Qwen3.6-9B-Q4 做架构解析），目标是 **4B 微调版在管线任务上追平 9B 通用版**，让无独显/小显存用户跑全 LLM 管线。
> 结构性优势：AST 锚点机制（LLM 只准引用符号名 → 服务端解析 AstNodeRef）从机制上限制小模型幻觉损害，这是敢用 0.8B~4B 的底气压舱石。

### 6.1 四级成本梯度（现有 L/M/H 的扩展）

| 档位 | 执行者 | 适用 | 边际成本 |
|---|---|---|---|
| L 确定性 | codegraph / L 级提取（零 LLM） | 代码事实层 | ≈0 |
| **S 微调小模型（本专项新增）** | Qwen3.5-0.8B~4B / MiniCPM5-1B/2B 微调 | 高频模式化任务（见 §6.2/§6.3） | 极低 |
| M 大本地模型 | Qwen3.6-9B 级 | 综合归纳、多轮工具调用 | 中 |
| H 云端 | DeepSeek 等旗舰 | 长链推理、交互对话 | 按量 |

### 6.2 任务-模型匹配矩阵（分析管线）

| 管线任务（prompt 模板） | 频率 | 微调档位 | 硬件下限 |
|---|---|---|---|
| 社区/组件命名（community_name） | 极高 | 0.8B~1B | 纯 CPU |
| 边缘/源码解释、伪代码（edge_explain / src_to_pseudocode） | 高 | 1~2B | CPU/入门卡 |
| 文件预摘要（pre_summary，当前数小时级瓶颈） | **最高** | 2B | 4~6G 显存 |
| 语义资产 M 级归纳、变更摘要 | 高 | 2~4B | 6~8G 显存 |
| 组件分析（agentic_component_analyst，带工具调用） | 中 | 4B | 8G 显存 |
| 整体架构生成 / 需求 agent / chat 对话 | 低 | M/H 档（不微调） | — |

### 6.3 闭环链路能力分级（围栏 → 编码 → bug 修复）

> 对 architect 黄金路径三环节的小模型胜任力结论（详细论证见 [local-small-model-finetune.md](local-small-model-finetune.md) 第二部分，本文只记结论）：

| 环节 | 可下沉到 S 档（微调小模型） | 必须保留 M/H 档 |
|---|---|---|
| 需求围栏 / 方案安全围栏 | **"编译器"角色**：已裁决架构模式的约束实例化（禁则展开、验收标准格式化）、需求覆盖度检查、围栏自洽性/符号锚定校验（生成-验证分离中的验证侧） | **"裁决者"角色**：架构档位判断（低/中/高配）、需求冲突仲裁、非功能权衡 |
| 围栏之上的编码 | **有条件胜任**，四前提：①任务原子化（Task_Graph）②约束密度到函数签名/禁则级③上下文经语义资产精确注入④单测验收自动化。胜任区间：单函数实现、CRUD/样板层、测试用例、机械迁移 | 跨文件重构、隐式全局约定、设计性/性能敏感代码 |
| bug 修复 | L1 编译/静态错误（规则或 0.8~2B）；L2 定位明确的测试失败（2~4B 微调，"失败输出+局部代码→patch"模式化） | L3 症状≠根因、需跨文件定位（7~14B 本地+工具调用）；L4 架构性/并发/需求误解（云端旗舰+人工） |

> 洞察：修复所需模型级别与**反馈回路质量成反比**——单测验收门禁（arch_unit_tests）把大量 L3 降级为 L2，是让小模型能接管修复的关键前提。黄金路径的模型成本曲线呈**哑铃型**：大模型在头（裁决/mandate）与尾（L3+ 修复），小模型在腰（围栏展开/编码/L2 修复）。

### 6.4 数据战略：管线自造血

```
热门开源项目（资源中心语料）
   │  教师模型（云端旗舰）跑完整管线
   ├── (管线真实 prompt, 教师 completion) 对 ……………… 蒸馏训练集
   ├── L 级 codegraph 确定性事实 ……………………………… 过滤脏样本（符号不存在/行号臆造直接丢弃）
   └── 用户采纳行为（命名/摘要是否被接受）……………… 后期 DPO 偏好数据
```

- 采集近零成本：`openai_compat.py` 已记 `[LLM_REQ]` 全量日志，补本地脱敏采集器落 jsonl（默认不出本机，守隐私承诺）
- 编码侧语料复用：开源项目真实 commit 对（测试通过前/后）+ mandate 约束注入
- 资源中心协同：预分析项目 = 获客内容 + 训练语料；微调模型 = 资源中心分发物 → 商业化路径 a/b 同时加强

### 6.5 工程与评测要点

- **方法**：QLoRA 按任务组训 adapter（4B 单卡 24G 可训）；训练目标必须含**结构化 JSON 输出 + function-call 格式**（对齐 `get_tool_definitions` 四 toolkit 与 output_schema），这是小模型上管线的生死线
- **成对版本**：prompt 模板与微调模型成对版本化，模板改动触发回归评测，防线上静默漂移
- **分发**：Q4_K_M/Q5 GGUF + Ollama Modelfile（provider 体系全 OpenAI 兼容，零架构改动）
- **评测门禁（管线级，不用通用 benchmark）**：

| 指标 | 门槛 |
|---|---|
| 结构化输出合法率 | ≥ 99% |
| 符号可解析率（AST 锚点命中） | ≥ 97% |
| 预摘要相对教师质量（ROUGE + 采纳率） | ≥ 85% |
| 组件命名采纳率 | 对标 9B 通用版 ±5% |
| 端到端（黄金路径完成率 / 全量分析耗时） | 微调 4B ≈ 通用 9B，耗时 ↓50% |

### 7.2 现阶段必须守住的三条原则

1. **本地数据主权**：一切云同步显式 opt-in；README 隐私承诺（"解析、图计算、架构分析均在本地"）是产品信用底线，任何路径不得默认破坏。
2. **项目库/主库分离**（G 设计）：天然切出"个人免费 / 跨项目共享付费"边界，Phase 2 的 P2-T6 实现时不得合并库。
3. **MCP 审计完整性**：所有工具调用必须落 arch_mcp_calls，为路径 b 保留计费前提。

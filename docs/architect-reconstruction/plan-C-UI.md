# Architect 重建 · 界面变化明细（Plan C 配套）

> 版本 v1.0 | 日期 2026-08-30 | 配套主文档：`plan-C.md`（v1.1）
> 本文档只描述**本次改版后 architect 前端界面**的变化（before → after），不含后端/schema/协议（见 plan-C）。
> 原则贯穿：architect 不决策 → 界面上所有"判定/通过/打回/确认"动作都归于设计者；事实与参考意见双通道呈现；覆盖度诚实；按需提取。

## 2. 资产管理主工作区（asset-mgmt）

### 2.1 顶部工具栏（before → after）

| 位置 | 改版前 | 改版后 | 说明 |
|---|---|---|---|
| 提取按钮 | 「提取语义资产」一键全量扫描 + 进度条 + 停止 | **移除全量提取**；改为「对话提取」入口（聚焦对话框并预填提示语），按需由对话触发 | plan-C §4：不走全量扫描 |
| 一致性 reconcile | 保留 | 保留，语义不变（升格为"全流程校验器"，UI 显示粒度不变） | plan-C §2.2 |
| [新增] 覆盖度徽标 | — | 显示 `已提取 n / 覆盖组件 m / 过期 k`，悬停列出"从未提取的组件/文件" | plan-C §4.3：覆盖度诚实 |
| 历史会话 | 保留 | 保留 | — |

### 2.2 语义 tab（semantic）

| 区块 | 改版前 | 改版后 |
|---|---|---|
| 行信息 | 名称 + 类别徽标 + 粒度 + desc | 增加**来源徽标**（用户/规约/LLM 生成，色区分）与**结构摘要 chips**（`5字段·6步·2分支·3关系`，一眼可扫，无需展开） |
| 展开详情 | fields/steps/branches + 伪码解释 | 增加**命名历史**（当前名+历史名+来源+时间，含失效名灰显"参考"）与**资产管理操作**（改名/合并/拆分，见 §2.4） |
| 行尾操作 | 刷新按钮 | 刷新 + 「问 agent」保留 + 「对话提取」 |
| 过滤器 | 类别/粒度下拉（6 kinds × 3 levels 硬编码） | 类别/粒度下拉**读框架配置**（档位裁剪后只显示启用的值域；自定义值显示用户标签） |
| [新增] 状态列 | — | 过期/失效/未锚定状态可视化（对应覆盖度诚实） |

### 2.3 组件 tab（component）

- 每个组件行新增「**对话提取**」入口：点击 → 右栏对话预填"提取组件 `<name>` 的语义资产"并发送，走 agent 提议→确认→执行（plan-C §4.1 触发提议制）。
- 组件行显示本组件**资产覆盖状态**（已提取/部分/未提取/过期），来自覆盖度统计。

### 2.4 资产管理操作（改名 / 合并 / 拆分）

单机模式（无主 KB）：
- **改名**：详情面板内联改名（只动认知层，锚点不动）；保存时若违反规约给出**黄色提示但不阻止**；改名写入命名历史（来源=用户）。
- **合并**：多选资产 → 「合并」→ 弹出确认（目标资产名、锚点并集预览、detail 冲突标记列表、关系重定向说明）→ 确认执行，留审计。
- **拆分**：选中资产 → 「拆分」→ agent 提案划分方案（哪些锚点/步骤归哪个新资产）→ 设计者调整 → 确认执行。

主 KB 模式：上述操作**按钮变灰并跳转主 KB 编辑台**（见 §6），agent 可代填提案后深链。

## 3. 语义图谱（SemanticGraphView）

| 能力 | 改版前 | 改版后 |
|---|---|---|
| 过滤 | 类别/粒度下拉（硬编码） | 下拉改读框架配置；**新增轴过滤条**：自定义轴/值域作为标签过滤（只影响显示，不生成视图） |
| 覆盖度 | 无 | **覆盖度图层**：未提取组件/文件灰化或虚线框；过期资产红色描边（可开关） |
| 期望 vs 实际 | 无 | **双图对照模式**：L2 行为比对时并排渲染"期望子图（契约条目）"与"实际子图（提取资产）"，差异边/缺失节点高亮（差异点点击 → 差异报告） |
| 节点信息卡 | desc/detail/锚点/伪码 | 增加：**关联资产**（图边可点击跳转）、**名称来源徽标**、**契约条目引用**（该节点被哪些契约条目命中/缺失） |

> 双图对照默认复用既有 7 视图与 `diagram.build` 管线，不 fork 第二套 IR（plan-C §11 护栏）。

## 4. 右栏对话（AnalysisChat）

改版后对话从"检索答疑"升级为**认知对齐主界面**，新增三类结构化卡片（沿用现有 `turns.assets` 卡片通道）：

| 卡片类型 | 触发 | 交互 | 对应 plan-C |
|---|---|---|---|
| **提取提案卡** | agent 检索发现资产缺失/过期 | 展示 `范围 + 理由 + 预估资产数`，按钮「确认提取 / 拒绝」 | §4.1 触发提议制 |
| **契约条目固化卡** | 方案讨论中 agent 把期望转结构化 | 逐条展示 `本体类型+锚点期望+行为期望+Z 轴约束+验收方式`，每条可「确认 / 修改 / 删」；未确认条目不进入契约包 | §6.1 对话式固化 |
| **差异报告卡** | runner 完成 / git diff 触发验收 | 按 L1/L2/L3 分区：L1/L2 事实列表（条目 id+实际资产 id+锚点+差异描述，可跳转证据）；L3 参考意见区（标注"模型意见"+置信度）；底部设计者动作「通过 / 打回 / 改期望」 | §6.2/§6.3 |

交互细节：
- **证据链跳转**：任何条目/差异行的"锚点"或"原话引用"可点击 → 跳源码视图/对话原文位置。
- **事实/意见双通道**：L1/L2 与 L3 视觉分区（如分隔线+标签"事实" / "模型参考意见"），意见区永不混入事实区。
- **角色指示**：输入区旁显示当前角色（提取/验收/归纳/伪码，plan-C §9），busyLabel 复用现有"正在调用工具 xxx…"。

## 5. 需求工作台（requirements）

- **分析对话**：`diagramSkill`（📐）旁新增 **「期望固化」开关（🧾）**，开启后 agent 在方案讨论中主动产出契约条目固化卡（§4）。
- **[新增] 契约包/验收 tab**：当前需求对应的契约条目列表（状态机 `draft→confirmed→injected→verifying→accepted/rejected`）、契约包总览（增量条目 + 引用资产 id + 组件引用 + Z 轴条目）、验收报告入口（对应差异报告卡的历史归档）。

## 6. 命名治理界面

### 6.1 规约（命名规约）
- **列表视图**：规约条目（作用域 project/component、适用类别、规则文本、来源 归纳/手写、状态），按组件分组。
- **归纳提议卡**：agent 在对话中检测到用户改名重复模式 → 提议新规约 → 「确认固化为规约 / 忽略」；确认后进入规约列表（plan-C §5.3，默认开启）。
- **编辑**：手写/修改规约、作用组件选择、停用。

### 6.2 术语表（词典）
- **列表/编辑**：词条映射（规范词→解释/英文对应），纯参考。
- **导入**：从项目文档/词汇表文件导入生成（格式待定，见 plan-C §13）。

### 6.3 主 KB 编辑台（多用户模式，本期 schema 留位）
- 改版后为主 KB 模式的**唯一认知层编辑入口**：改名/合并/拆分全部在此完成（agent 可携带提案深链进入，人确认执行）。
- 展示各编辑的**审计记录**（谁/何时/为什么）；名称变更 bump 版本后，各实例 reconcile 刷新。
- 单机模式下此界面隐藏（编辑在 asset-mgmt 就地完成）。

## 7. 设置页（config）

| 区块 | 内容 |
|---|---|
| **认知框架** | 档位选择（低/中/高，项目级）；值域裁剪/扩展（X/Y 轴值启用勾选）；[高级] 自定义轴编辑器（轴 id/标签/值域列表）；框架版本与变更留痕；切换档位时的**归档迁移确认**（被裁 kind 存量资产 → 归档提示） |
| **角色模型** | tAgent 角色 → 模型/API 映射表（提取/验收/归纳/伪码），三级优先级说明（全局偏好 < 项目级 < 主 KB 下发） |

## 9. 分期落地（与 plan-C §12 对齐）

| 阶段 | 界面变化 |
|---|---|
| **M1（底座配置化 + 按需提取）** | 顶部全量提取按钮移除 → 对话提取入口；语义行来源徽标/结构摘要；组件行对话提取；覆盖度徽标；config 认知框架（档位/值域）；角色模型映射 |
| **M2（正向闭环）** | 对话提取提案卡/契约条目固化卡；需求工作台 🧾 开关 + 契约包 tab；图谱双图对照 + 轴过滤；L1/L2 差异报告卡；改名/合并/拆分就地操作（单机） |
| **M3（验收收敛 + 治理完备）** | L3 参考意见双通道呈现；命名治理界面（规约列表/归纳提议卡/术语表导入）；主 KB 编辑台；验收报告归档 |
| 后置 | 部署/运维视图、多人合并冲突解决 UI、外部 coding agent 对接 |

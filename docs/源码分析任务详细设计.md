### 1.2 创建任务

**触发**: 用户点击"新建任务"按钮

**流程**:
```
UI (TaskCreateForm.vue)
  │
  ├─ 1. 展示 FileStatsPanel，自动扫描项目文件分布
  │     └─ scanFileStats(projectId) → 返回 extensions/directories 统计
  │
  ├─ 2. 用户填写表单
  │     ├─ 任务名称 (必填)
  │     ├─ 目录范围 (多选，默认全部)
  │     ├─ 文件类型 (多选，从文件分布中勾选)
  │     ├─ 排除目录 (逗号分隔)
  │     ├─ 匹配模式 (all/glob/regex + 自定义模式)
  │     └─ 报告类型 (dependency/callChain/dataFlow)
  │
  ├─ 3. 点击"保存配置"
  │     └─ handleSubmit() → analysisStore.createTask(params)
  │
  ├─ 4. IPC 调用
  │     └─ ipc.analysis.createTask(params) → window.api.analysis.createTask()
  │
  ├─ 5. Electron 桥接
  │     └─ preload → ipcMain.invoke('ipc:call', 'analysis.createTask', params)
  │
  ├─ 6. ZeroMQ RPC
  │     └─ zmqRouter.call('analysis.createTask', params) → Python 后端
  │
  ├─ 7. 后端处理 (create_task)
  │     ├─ 生成 UUID v4 作为 task_id
  │     ├─ 将数组字段 JSON 序列化 (scopes/extensions/exclude_dirs/report_types)
  │     ├─ INSERT INTO analysis_tasks
  │     ├─ SELECT * 读取完整记录
  │     └─ JSON 解析数组字段后返回
  │
  └─ 8. 前端响应
        ├─ analysisStore 将新任务 push 到 tasks 数组
        ├─ emit('created', taskId)
        └─ HomePage 关闭 taskCreate tab，切换回任务列表
```

**任务类型**:
| 类型 | 值 | 说明 |
|------|---|------|
| AST 分析 | `ast` | 语法树解析 |
| 调用链分析 | `call-chain` | 函数调用关系 |
| 依赖分析 | `dependency` | 模块/文件依赖 |
| 数据流分析 | `dataflow` | 数据流向追踪 |
| 全量分析 | `full` | 以上全部 |

### 1.3 编辑任务配置

**触发**: 用户在任务列表点击"编辑"

**流程**:
```
UI (TaskListPanel → TaskCreateForm)
  │
  ├─ 1. 检查任务状态
  │     ├─ status = 'running' → 弹出"停止后编辑"确认
  │     │   └─ stopTask(taskId) → 等待停止 → 进入编辑
  │     └─ 其他状态 → 直接进入编辑
  │
  ├─ 2. 加载现有配置
  │     └─ analysisStore.getTask(taskId) → 填充表单
  │
  ├─ 3. 用户修改配置
  │
  ├─ 4. 点击"确认修改"
  │     └─ handleSubmit() → analysisStore.updateTaskConfig(taskId, config)
  │
  ├─ 5. 后端处理 (update_task_config)
  │     ├─ 校验任务不在 running 状态
  │     ├─ 读取当前任务配置
  │     ├─ 保存旧配置到 task_config_history (审计追溯)
  │     ├─ UPDATE analysis_tasks (含 config_version++)
  │     ├─ status 设为 'pending' (标记需重新运行)
  │     └─ 返回更新后的任务
  │
  └─ 6. 前端响应
        ├─ 更新 tasks 数组中的任务
        └─ 关闭编辑 tab，返回任务列表
```

**配置变更审计**: 每次修改都会将旧配置快照写入 `task_config_history` 表，包含 `config_version`、所有配置字段和变更时间。

### 1.4 执行分析

**触发**: 用户在任务列表点击"运行"

**流程**:
```
UI (TaskListPanel)
  │
  ├─ 1. 用户点击运行
  │     └─ analysisStore.runTask(taskId)
  │
  ├─ 2. IPC 调用
  │     └─ ipc.analysis.runTask(taskId) → Python 后端
  │
  ├─ 3. 后端处理 (run_task) — async
  │     ├─ 校验任务存在且不在 running 状态
  │     ├─ 查询当前最大 run_number
  │     ├─ 生成 run_id (UUID v4)
  │     ├─ INSERT INTO analysis_task_runs (快照当前配置)
  │     ├─ UPDATE analysis_tasks SET status='running', progress=0
  │     ├─ asyncio.create_task(_execute_task(...))  ← 后台启动
  │     └─ 立即返回 {taskId, runId, runNumber, status: 'running'}
  │
  └─ 4. 前端响应
        ├─ 更新本地任务状态为 'running'
        └─ 进度条归零
```

### 1.5 异步执行管线

**架构**: asyncio 调度器 + ThreadPoolExecutor 工作线程

```
┌─────────────────────────────────────────────────────────────────┐
│                    异步执行时序图                                 │
│                                                                 │
│  Event Loop              ThreadPool (4 workers)                 │
│  (asyncio)               (parse_executor)                       │
│       │                              │                          │
│       │  _execute_task()             │                          │
│       │  ┌───────────────────────────┤                          │
│       │  │ submit(_do_parse, ...)    │                          │
│       │  │                           │                          │
│       │  │ (立即返回)                 │  _do_parse() 阻塞执行     │
│       │  ├───────────────────────────▶                          │
│       │  │                           │                          │
│       │  │ 返回前端                  │  1. 加载项目库            │
│       │  │                           │  2. 遍历 source_files    │
│       │  │                           │  3. Tree-sitter 解析     │
│       │  │                           │  4. 生成 AST/调用链/依赖  │
│       │  │                           │  5. 写入 analysis_reports│
│       │  │                           │                          │
│       │  │                           │  _update_progress()      │
│       │  │  ◀───────────────────────  │ (每处理 5 个文件)       │
│       │  │  server.publish()         │                          │
│       │  │  task.progress            │                          │
│       │  │  ────────────────────────▶│ ──▶ 前端 UI 更新         │
│       │  │                           │                          │
│       │  │                           │  完成/异常                │
│       │  │  ◀───────────────────────  │                          │
│       │  │  server.publish()         │                          │
│       │  │  task.complete/error      │                          │
│       │  │  ────────────────────────▶│ ──▶ 前端 UI 更新         │
│       │  │                           │                          │
│       │  │  更新 DB 最终状态          │  线程释放                 │
│       │  └───────────────────────────┘                          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**线程池配置**:
```python
parse_executor = ThreadPoolExecutor(max_workers=4, thread_name_prefix="parse-worker")
```

**进度回调** (`_update_progress`):
```python
def _update_progress(current: int):
    # 1. 更新 analysis_tasks (progress, current, updated_at)
    # 2. 更新 analysis_task_runs (progress, current)
    # 3. 发布 ZeroMQ 事件
    server.publish("task", "progress", {
        "taskId": task_id,
        "runId": run_id,
        "progress": int,
        "total": int,
        "current": int
    })
```

### 1.6 Tree-sitter 真实解析流程（已实现）

> **2026-05-11 更新**: `_do_parse()` 已从 mock 替换为 Tree-sitter 真实解析，代码位于 `backend/analyst_runner.py`。

```
_execute_task(server, main_db, task_id, run_id, start_time)
  │
  ├─ 1. 加载任务配置
  │     └─ TaskStore.get_task(task_id)
  │
  ├─ 2. 获取项目库 + 文件列表 (应用 scopes/extensions/exclude_dirs/pattern 过滤)
  │     └─ project_db = multi_db.get_project_db(project_id)
  │     └─ SELECT file_path, language, size FROM source_files WHERE ...
  │
  ├─ 3. 按语言分片 + 线程池并行解析 AST
  │     ├─ TreeSitterASTParser.parse_file(file_path, content)
  │     ├─ 单文件最多 100K AST 节点
  │     ├─ >500KB 文件跳过
  │     └─ 写入 base_node 表
  │
  ├─ 4. 提取符号 (函数/类/宏/方法)
  │     └─ BaseSymbolExtractor → graph_node (symbol_node_type=function/class/macro/method)
  │
  ├─ 5. 构建调用图
  │     └─ BaseCallGraphExtractor → graph_node (symbol_node_type=call_relation)
  │
  ├─ 6. 构建依赖图
  │     └─ BaseDependencyExtractor → graph_node (symbol_node_type=dependence)
  │
  ├─ 7. 社区分析 (Louvain 算法)
  │     ├─ analyze_communities() → graph_doc + community_hierarchy
  │     ├─ INCLUDE 图: 最小 6 节点
  │     ├─ CALL 图: 最小 20 节点
  │     └─ 最多 6 层递归
  │
  ├─ 8. 汇总统计 → analysis_reports (主库)
  │     └─ total_ast_nodes, total_symbols, total_call_edges,
  │         total_dep_edges, total_communities, language_stats, ...
  │
  ├─ 9. 更新最终状态
  │     ├─ UPDATE analysis_tasks SET status='done', progress=100
  │     ├─ UPDATE analysis_task_runs SET status='done',
  │     │   finished_at, duration_ms
  │     └─ server.publish("task", "complete", {...})
  │
  └─ 10. 异常处理
        ├─ 单个文件解析失败 → 记录日志，继续下一个
        └─ 致命错误 → UPDATE status='error', publish("task", "error", {...})
```

**实现文件**:
| 步骤 | 文件 | 函数 |
|------|------|------|
| 入口 | `backend/task_manager.py` | `run_task()` |
| 执行器 | `backend/analyst_runner.py` | `_execute_task()` |
| AST 解析 | `backend/parsers/ast_parser.py` | `TreeSitterASTParser.parse_file()` |
| 符号提取 | `backend/parsers/symbol_extractor.py` | `BaseSymbolExtractor` |
| 调用图 | `backend/parsers/call_graph_extractor.py` | `BaseCallGraphExtractor` |
| 依赖图 | `backend/parsers/dependency_extractor.py` | `BaseDependencyExtractor` |
| 社区分析 | `backend/community_analysis.py` | `analyze_communities()` |
| 语言处理器 | `backend/parsers/languages/*/parser.py` | 7 种语言 |

### 1.8 停止任务

**流程** (当前):
```
analysisStore.stopTask(taskId)
  → ipc.analysis.stopTask(taskId)
  → 后端 stop_task()
    ├─ 校验任务存在且 status = 'running'
    ├─ UPDATE analysis_tasks SET status='stopped'
    ├─ UPDATE analysis_task_runs SET status='stopped', finished_at
    └─ 返回 {taskId, status: 'stopped'}
  → 前端更新本地任务状态
```

> ⚠️ 当前 `stopTask` 不发布 ZeroMQ 事件，前端订阅者不会收到通知

**目标扩展** (D7 — 停止/继续/重新执行):
```
stopTask(taskId)     → status: running → paused,  发布 task.stopped
resumeTask(taskId)   → status: paused → running,  恢复 _execute_task
cancelTask(taskId)   → status: running/paused → stopped, 发布 task.stopped
```

需修改 `analysis_tasks.status` CHECK 约束，新增 `'paused'` 状态。

### 1.9 重新运行

### 1.11 删除任务

**流程**:
```
analysisStore.deleteTask(taskId)
  → ipc.analysis.deleteTask(taskId)
  → 后端 delete_task()
    └─ DELETE FROM analysis_tasks WHERE id = ?
      → CASCADE 删除:
        ├─ analysis_task_runs (该任务所有运行记录)
        ├─ analysis_reports (该任务所有报告)
        └─ task_config_history (该任务所有配置历史)
  → 前端从 tasks 数组移除，清除选中状态
```

## 二、技术接口

### 2.1 前端类型定义

#### AnalysisTask

```typescript
interface AnalysisTask {
  id: string                    // UUID v4
  projectId: string             // 所属项目
  type: 'ast' | 'call-chain' | 'dependency' | 'dataflow' | 'full'
  name: string
  status: 'pending' | 'modified' | 'running' | 'done' | 'error' | 'cancelled' | 'stopped'
  progress?: number             // 0-100
  total?: number                // 总文件数
  current?: number              // 当前处理到第几个
  error?: string | null
  createdAt: string
  updatedAt: string
  favorite?: boolean
  pinned?: boolean
  tags?: string[]
  // 配置字段
  scope?: string                // 旧: 单选目录
  scopes?: string[]             // 新: 多选目录
  extensions?: string[]         // 文件后缀过滤
  excludeDirs?: string[]        // 排除目录
  reportTypes?: string[]        // ['dependency', 'callChain', 'dataFlow']
  patternType?: string          // 'all' | 'glob' | 'regex'
  pattern?: string              // 自定义匹配模式
  // 运行统计
  configVersion?: number
  lastRunId?: string
  runCount?: number
  lastRunStatus?: string
  lastRunNumber?: number
}
```

#### TaskRun

```typescript
interface TaskRun {
  id: string
  taskId: string
  runNumber: number             // 自增序号
  status: 'running' | 'done' | 'error' | 'stopped'
  progress: number
  total: number
  current: number
  error?: string | null
  startedAt: string
  finishedAt?: string
  durationMs?: number
  snapshotScope?: string[]      // 运行时的配置快照
  snapshotExtensions?: string[]
  snapshotExcludeDirs?: string[]
  snapshotReportTypes?: string[]
}
```

```typescript
interface FileStatsResult {

```

```typescript
interface ScanOptions {
  scopes?: string[]

  selectedExtensions?: string[]
  patternType?: 'all' | 'glob' | 'regex'

  excludeDirs?: string[]
}
```

#### TaskConfigUpdate

```typescript
interface TaskConfigUpdate {

  extensions?: string[]
  excludeDirs?: string[]

```

```typescript
interface AnalysisResult {
```

## 三、协议规范

### 3.1 ZeroMQ RPC 协议

#### 3.1.1 基础设施文件位置

ZMQ RPC 基础设施分布在 Python 后端和 Electron 主进程两端：

**Python 后端** (`backend/` 目录):

| 文件 | 路径 | 职责 |
|------|------|------|
| `zmq_server.py` | `backend/zmq_server.py` | ZMQServer 类：DEALER socket 接收请求、PUB socket 发布事件、方法注册表 |
| `core_service.py` | `backend/core_service.py` | 56 个业务方法注册（`@server.register("method.name")`） |
| `main.py` | `backend/main.py` | 入口：启动 ZMQServer、初始化 logging、加载业务模块 |
| `sqlite_ctx.py` | `backend/sqlite_ctx.py` | MultiDBManager：数据库连接池、LRU 缓存、WAL 模式 |
| `plantuml_service.py` | `backend/plantuml_service.py` | PlantUML 渲染服务 |

**Electron 主进程** (`electron/` 目录):

| 文件 | 路径 | 职责 |
|------|------|------|
| `zmq-router.ts` | `electron/zmq-router.ts` | ZMQRouter 类：DEALER socket 发送请求、SUB socket 订阅事件、请求-响应匹配 |
| `python-bridge.ts` | `electron/python-bridge.ts` | PythonBridge 类：启动/停止 Python 子进程、传递 ZMQ 端口环境变量 |
| `main.ts` | `electron/main.ts` | Electron 入口：初始化 PythonBridge + ZMQRouter、注册 IPC handler |
| `preload.ts` | `electron/preload.ts` | contextBridge：暴露 `window.api` 给渲染进程 |

**通讯链路**:
```
Vue 组件
  → ipc.ts (前端适配层)
    → window.api (preload.ts 暴露)
      → ipcRenderer.invoke('ipc:call', method, params)
        → main.ts (ipcMain.handle('ipc:call'))
          → zmqRouter.call(method, params)  ← electron/zmq-router.ts
            → ZeroMQ DEALER (port 5671)
              → ZMQServer.handle_request()  ← backend/zmq_server.py
                → method(**params)  ← backend/core_service.py
```

#### 3.1.2 端口

| 端口 | Socket | 方向 | 用途 |
|------|--------|------|------|
| 5671 | DEALER | Electron → Python | RPC 请求/响应 |
| 5680 | PUB/SUB | Python → Electron | 事件推送 |

环境变量: `ZMQ_DEALER_PORT`, `ZMQ_PUB_PORT`

#### 3.1.3 请求格式 (3 帧)

```
Frame 1: requestId    (UTF-8, 如 "req-1")
Frame 2: method       (UTF-8, 如 "analysis.createTask")
Frame 3: params_json  (UTF-8, JSON 字符串)
```

#### 3.1.4 响应格式 (3 帧)

```
Frame 1: requestId    (UTF-8, 与请求对应)
Frame 2: result_json  (UTF-8, JSON 字符串，失败时为 null)
Frame 3: error_json   (UTF-8, JSON 字符串，成功时为 null)
```

#### 3.1.5 错误格式

```json
{"code": -32000, "message": "Error description"}
{"code": -32601, "message": "Method not found: xxx"}
```

#### 3.1.6 超时

- 请求超时: 30 秒后 reject
- 连接关闭: 所有 pending 请求 reject

### 3.2 事件推送协议

#### 3.2.1 格式 (3 帧)

```
Frame 1: topic        (UTF-8, 如 "task")
Frame 2: event_type   (UTF-8, 如 "progress")
Frame 3: data_json    (UTF-8, JSON 字符串)
```

#### 3.2.2 分析任务事件

### 4.2 MultiDBManager

```python
class MultiDBManager:
    # LRU 缓存，最多 3 个打开的连接
    # WAL 模式，busy_timeout=5000ms
    # synchronous=NORMAL, cache_size=10000
    
    def get_project_db(project_id: str) -> SQLiteContext:
        """获取项目库连接，自动缓存/回收"""
```

### 4.3 并发安全

- **WAL 模式**: 多读一写并发
- **busy_timeout=5000ms**: 写冲突等待 5 秒
- **synchronous=NORMAL**: 性能与安全平衡
- **LRU 缓存**: 最多 3 个打开的数据库连接，超出时回收最久未用

### 6.3 决策补充说明

#### D6: JSONL 导出格式

```
{"taskId": "...", "runId": "...", "type": "ast", "file": "src/main.ts", "data": {...}}
{"taskId": "...", "runId": "...", "type": "callChain", "caller": "main()", "callee": "init()"}
{"taskId": "...", "runId": "...", "type": "dependency", "source": "main.ts", "target": "utils.ts"}
{"taskId": "...", "runId": "...", "type": "dataflow", "variable": "x", "from": "main.ts:10", "to": "utils.ts:5"}
```

每行一条 JSON 记录，便于流式处理和下游消费。

#### D7: 任务控制扩展

**状态机扩展**:
```
pending → running → done
         ↓         ↑
       paused ←───┘
         ↓
       running (resume)
         ↓
       stopped (不可恢复)
```

| 操作 | 前置状态 | 后置状态 | 事件 |
|------|---------|---------|------|
| `runTask` | pending/modified/done/error/stopped | running | — |
| `stopTask` (暂停) | running | paused | `task.stopped` |
| `resumeTask` | paused | running | — |
| `cancelTask` | running/paused | stopped | `task.stopped` |
| `reRunTask` | done/error/stopped | running | — |

> 当前 `stopTask` 将状态设为 `'stopped'`（不可恢复），D7 需区分"暂停"(paused)和"终止"(stopped)。

#### D8: selectedExtensions 过滤

`scanFileStats` 的 SQL 查询在 `ext_where` 基础上追加:
```sql
AND language IN ('vue', 'ts', 'js')  -- 对应 selectedExtensions 参数
```

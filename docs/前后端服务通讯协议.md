> 最后更新: 2026-05-21 | ZeroMQ RPC + Electron IPC | **95** 个后端方法 (12 模块) | LLM 三模式 + 会话/模板/分组管理

## 一、通讯架构

```
┌────────────────────────────────────────────────────────────────┐
│                        通讯链路                                 │
│                                                                │
│  Vue 组件 ──ipc.ts──► window.api ──IPC──► main.ts ──ZMQ──► Python │
│   (前端)     适配     (preload)   (Electron)  (zmq-router)  (后端)  │
│                │           │           │              │         │
│                │           │           │              │         │
│   snake↔camel  │  3-frame  │  invoke/  │  DEALER     │  75     │
│   转换         │  消息格式  │  on       │  + SUB      │  方法   │
└────────────────────────────────────────────────────────────────┘
```

### 1.1 三层通讯

| 层 | 协议 | 方向 | 说明 |
|---|------|------|------|
| **L1: 前端 ↔ preload** | `window.api` | 双向 | TypeScript 接口，`contextBridge` 暴露 |
| **L2: preload ↔ main** | Electron IPC | 双向 | `ipcRenderer.invoke()` / `ipcMain.handle()` |
| **L3: main ↔ Python** | ZeroMQ | 双向 | DEALER (RPC) + PUB/SUB (事件) |

## 二、ZeroMQ 协议

### 2.1 端口分配

| 端口 | Socket | 方向 | 用途 |
|------|--------|------|------|
| **5671** | DEALER | Electron → Python | RPC 请求/响应 |
| **5680** | PUB/SUB | Python → Electron | 事件推送 |

> 端口由环境变量 `ZMQ_DEALER_PORT` / `ZMQ_PUB_PORT` 控制

### 2.2 RPC 消息格式（3 帧）

**请求 (Electron → Python)**:
```
Frame 1: requestId    (UTF-8, 如 "req-1")
Frame 2: method       (UTF-8, 如 "project.list")
Frame 3: params_json  (UTF-8, JSON 字符串)
```

**响应 (Python → Electron)**:
```
Frame 1: requestId    (UTF-8, 与请求对应)
Frame 2: result_json  (UTF-8, JSON 字符串，失败时为 null)
Frame 3: error_json   (UTF-8, JSON 字符串，成功时为 null)
```

### 2.3 事件推送格式（3 帧）

```
Frame 1: topic        (UTF-8, 如 "task")
Frame 2: event_type   (UTF-8, 如 "progress")
Frame 3: data_json    (UTF-8, JSON 字符串)
```

Electron 端订阅主题: `task`, `project`, `backend`, `llm`

事件转发到前端: `event:{topic}.{eventType}` (如 `event:task.progress`)

**llm 事件类型** (LLM 流式对话使用 `window.api.llm.subscribe` 订阅，不通过 event: 通道):

| 事件类型 | 数据字段 | 触发时机 |
|---------|---------|---------|
| `chunk` | `{requestId, index, text}` | 每 100ms 或 200 字符 |
| `tool_call` | `{requestId, toolName, args}` | LLM 请求调用工具 |
| `tool_result` | `{requestId, toolName, result}` | 工具执行完毕 |
| `done` | `{requestId, content, usage}` | 流式完成 |
| `error` | `{requestId, message, code}` | 异常/超时/中止 |

### 2.4 超时与错误

| 场景 | 行为 |
|------|------|
| 请求超时 | 30 秒后 reject，错误 `"Request timeout: {method}"` |
| 连接关闭 | 所有 pending 请求 reject，`"Connection closed"` |
| JSON 解析失败 | 返回 `{code: -32000, message: "..."}` |
| zeromq 加载失败 | `process.exit(1)`（无 mock 回退） |

### 4.2 analysis.* (19 方法)

> **2026-05-11 更新**: 以下 13 个核心方法已从 mock 实现替换为 Tree-sitter 真实解析。底层通过 `analyst_runner._execute_task()` 执行 6 步分析流程（AST → 符号 → 调用图 → 依赖图 → 社区 → 汇总）。
> **2026-05-15 更新**: 新增 6 个报告/社区分析方法 (`getAvailableLevels`, `getCommunityGraph`, `getSymbolDetail`, `getEdgeDetail`, `getCascadeLevels`, `getQueryStats`)，analysis 模块共 19 个方法。

#### `analysis.listTasks` → `list_tasks(project_id/projectId)`
- **参数**: `project_id` 或 `projectId` (兼容两种命名)
- **返回**: `AnalysisTask[]` (LEFT JOIN `analysis_task_runs` 获取 `run_count`/`last_status`，JSON 字段已解析)

#### `analysis.createTask` → `create_task(projectId, type, name, scope, scopes, extensions, excludeDirs, reportTypes, patternType, pattern)`
- **参数**:
  - `projectId` — 项目 ID
  - `type` — `'ast'`/`'call-chain'`/`'dependency'`/`'dataflow'`/`'full'`
  - `name` — 任务名称
  - `scopes` — 多选目录数组 (新)
  - `extensions` — 文件后缀数组
  - `excludeDirs` — 排除目录数组 (自动映射为 `exclude_dirs`)
  - `reportTypes` — 报告类型数组 (自动映射为 `report_types`)
  - `patternType` — 匹配模式
  - `pattern` — 自定义模式
- **返回**: `AnalysisTask` (⚠️ JSON 字段未解析，前端需防御性处理)
- **字段映射**: `excludeDirs→exclude_dirs`, `reportTypes→report_types`

#### `analysis.runTask` → `run_task(taskId)` (async)
- **参数**: `taskId` — 任务 ID
- **返回**: `{"success": true, "run_id": str}` (创建 run 记录 + `asyncio.create_task(_execute_task)`)
- **执行流程**:
  1. 读取任务配置，过滤文件列表（scopes/extensions/excludes/pattern）
  2. 按语言分片，线程池并行解析 AST（tree-sitter，单文件最多 100K 节点，>500KB 跳过）
  3. 提取符号（函数/类/宏/方法）
  4. 构建调用图（call edges）
  5. 构建依赖图（import/include edges）
  6. 社区分析（Louvain 算法，INCLUDE 最小 6 节点，CALL 最小 20 节点，最多 6 层）
  7. 汇总统计，写入 `analysis_reports`（主库）+ `base_node`/`graph_node`/`graph_doc`（项目库）
- **进度推送**: 每步通过 `analysis.progress` 事件推送 `{taskId, progress, current, total, message}`
- **并发控制**: 单项目串行（`_running_tasks` 集合），支持 stop/resume/cancel

#### `analysis.getTask` → `get_task(taskId)`
- **参数**: `taskId` — 任务 ID
- **返回**: `AnalysisTask | None` (JSON 字段已解析为 JS 数组)

#### `analysis.getResults` → `get_results(taskId)`
- **参数**: `taskId` — 任务 ID
- **返回**: `AnalysisResult` — 包含统计摘要 + 结构化数据
  - 统计: `total_ast_nodes`, `total_symbols`, `total_call_edges`, `total_dep_edges`, `total_communities`, `language_stats`, `files_processed`, `skipped_files`
  - 旧格式: `ast`, `callChain`, `dependencies`, `dataflow` (从 `analysis_reports` 读取，保留兼容)
  - 新格式: ⚠️ `project.queryBaseNodes`/`project.queryGraphNodes` 文档中提及但**后端未实现**；当前前端无直接查询路径

#### `analysis.updateTask` → `update_task(taskId, **kwargs)`
- **参数**: `taskId` + `favorite`, `pinned`, `tags`
- **返回**: `AnalysisTask` (仅更新收藏/置顶/标签)

#### `analysis.deleteTask` → `delete_task(taskId)`
- **参数**: `taskId` — 任务 ID

#### `analysis.stopTask` → `stop_task(taskId)`

#### `analysis.scanFileStats` → `scan_file_stats(projectId, scope, scopes, patternType, pattern, excludeDirs, selectedExtensions)`
- **参数**: `projectId` + 筛选选项
- **返回**: `FileStatsResult` — `{extensions: Map, totalFiles, totalDirs, directories: DirTreeNode[]}`
- **说明**: 查询 `source_files`，支持 scopes/excludes/glob/regex 过滤。**文件统计** (`extensions`, `totalFiles`) 按 `scopes` 过滤，**目录树** (`directories`) 始终返回项目完整结构（不受 `scopes` 影响），`totalDirs` 为全量目录数

#### `analysis.getAvailableLevels` → `get_available_levels(taskId, edgeType)` (**新**)
- **参数**: `taskId` — 任务 ID, `edgeType` — 边类型 (`INCLUDE`/`CALL`)
- **返回**: `string[]` — 该任务实际生成的社区层级列表，如 `['L0', 'L1', 'L2']`
- **数据源**: `graph_doc` 表，`SELECT DISTINCT comm_lv`

#### `analysis.getCommunityGraph` → `get_community_graph(taskId, edgeType, commLv, commIds[], depth)` (**新**)
- **参数**:
  - `taskId` — 任务 ID
  - `edgeType` — 边类型 (`INCLUDE`/`CALL`)
  - `commLv` — 社区层级 (`L0`-`L5`)
  - `commIds` — 社区 ID 列表 (可选，不传则返回该层级所有社区)
  - `depth` — 展开深度 (默认 2，最大 4)
- **返回**: `{nodes: [], edges: [], communities: []}` — 按深度展开，最深层直接展示符号节点
- **数据源**: `graph_doc` 表，含 CALL 文件级汇聚 + INCLUDE 清理

#### `analysis.getSymbolDetail` → `get_symbol_detail(taskId, symbolId)` (**新**)
- **参数**: `taskId` — 任务 ID, `symbolId` — 符号 ID (`graph_node.id`)
- **返回**: `{name, type, file_path, start_line, end_line, code_snippet, needs_summarize}` — 默认 20 行代码抽样，超过标记 `needs_summarize=true`

#### `analysis.getEdgeDetail` → `get_edge_detail(taskId, edgeId)` (**新**)
- **参数**: `taskId` — 任务 ID, `edgeId` — 边 ID (`graph_node.id`)
- **返回**: `{source, target, edge_type, call_site / include_path, is_system}` — CALL 边返回调用位置，DEPENDENCE 边返回导入路径

#### `analysis.getCascadeLevels` → `get_cascade_levels(taskId, edgeType)` (**新**)

## 六、前端 IPC 服务层 (ipc.ts)

### 6.1 适配逻辑

```typescript
// ipc.ts 中的字段适配
function adaptProject(p: any): Project {
  return {
    ...p,
    rootPath: p.root_path,
    fileCount: p.file_count,
    needsResync: p.needs_resync,
    hasFileChanges: p.has_file_changes,
    isSample: p.is_sample,
    lastSync: p.last_sync,
    createdAt: p.created_at,
  }
}
```

### 6.2 浏览器环境限制

在浏览器环境 (`window.api` 不可用) 时：
- 事件回调 (`onProgress`/`onComplete`/`onError`/`onStatusChange`) 存储为 fallback，Electron 环境下自动激活
- RPC 方法调用会抛出 `TypeError`（无 mock 回退）
- ⚠️ 当前无浏览器环境的 mock IPC provider，应用必须在 Electron 中运行

### 6.3 方法调用链

```
Vue 组件
  → store.action(params)
    → ipc.module.method(params)
      → window.api.module.method(params)  // preload 桥接
        → ipcRenderer.invoke('ipc:call', method, params)  // Electron IPC
          → zmqRouter.call(method, params)  // ZeroMQ RPC
            → Python 后端方法
```

- 路径前缀校验，拒绝目录遍历

- `contextIsolation: true`
- `nodeIntegration: false`
- 所有主进程 API 通过 `contextBridge` 暴露

- 绑定 `127.0.0.1` (仅本地回环)
- 无认证机制 (本地应用，信任本地环境)

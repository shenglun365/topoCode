# 渲染架构评估报告

> 评估时间: 2026-05-05
> 目标: 整合 SVG / Mermaid / D3 / PIXI.js / PlantUML / 自定义动画，采用独立线程/进程渲染

---

## 一、各渲染引擎特性分析

| 引擎 | 计算类型 | 线程安全 | 内存占用 | 阻塞风险 | GPU 加速 | 输出格式 |
|------|---------|---------|---------|---------|---------|---------|
| **SVG (原生)** | DOM 操作 | ❌ 主线程 | 中 (DOM 节点) | < 200 节点低，> 1000 高 | ✅ CSS transform | SVG DOM |
| **Mermaid** | 同步解析 + SVG 生成 | ❌ 必须主线程 | 低 | **高** (复杂图 1-3s) | ❌ | SVG string |
| **D3.js** | 数据绑定 + 力导向迭代 | ⚠️ 计算可分离，DOM 需主线程 | 中 | **高** (d3-force 300+ tick) | ⚠️ 需 Canvas | SVG/Canvas |
| **PIXI.js** | WebGL 渲染 | ✅ 支持 OffscreenCanvas | 高 (纹理) | 低 (GPU) | ✅ 核心能力 | Canvas/WebGL |
| **PlantUML** | Java 进程调用 | ✅ 外部进程 | 高 (JVM) | **极高** (启动 2-5s) | ❌ | PNG/SVG |
| **自定义动画** | requestAnimationFrame | ❌ 必须主线程 | 低 | 低 (60fps 预算 16ms) | ✅ transform/opacity | CSS/Canvas |

## 二、技术方案对比

### 方案 A: 纯 Web Worker (推荐)

```
┌─────────────────────────────────────────────────────────────────┐
│                        UI 主线程 (Vue)                           │
│                                                                 │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────┐  │
│  │ Knowledge    │  │ TaskReport   │  │ AnimationPlayer      │  │
│  │ Graph.vue    │  │ .vue         │  │ .vue                 │  │
│  └──────┬───────┘  └──────┬───────┘  └──────────┬───────────┘  │
│         │ postMessage     │ postMessage          │ rAF          │
│         ▼                 ▼                      │              │
│  ┌─────────────────────────────────────────────┐  │              │
│  │         Web Worker Pool (统一管理)            │  │              │
│  │                                             │  │              │
│  │  ┌──────────────┐  ┌────────────────────┐  │  │              │
│  │  │ Mermaid      │  │ D3 Layout          │  │  │              │
│  │  │ Worker       │  │ Worker             │  │  │              │
│  │  │ → SVG string │  │ → node positions   │  │  │              │
│  │  └──────────────┘  └────────────────────┘  │  │              │
│  └─────────────────────────────────────────────┘  │              │
│         │                 │                       │              │
│         ▼ postMessage     ▼ postMessage           ▼              │
│    {type:'svg', data}  {type:'coords', data}   PIXI.js (主线程)   │
│         │                 │                       │              │
│         ▼                 ▼                       ▼              │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │              主线程渲染层 (接收结果)                          │ │
│  │  SVG: v-html / D3: 仅更新 DOM 属性 / PIXI: WebGL 渲染       │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

**优点:**
- ✅ 零额外进程开销，打包体积小
- ✅ 与主进程共享内存 (Transferable Objects)，大数据传输快
- ✅ Vite 原生支持 `new Worker(..., { type: 'module' })`
- ✅ 浏览器/Electron 环境统一，无需区分
- ✅ Worker 池统一管理，按需分配

**缺点:**
- ❌ 无法使用 Node.js API (fs, child_process)
- ❌ PlantUML 无法在 Worker 内运行 (需 Java)
- ❌ PIXI.js WebGL 上下文无法在 Worker 创建 (需 OffscreenCanvas + Canvas 2D 回退)
- ❌ Worker 调试困难 (Chrome DevTools 支持但体验差)

**适用场景:** Mermaid 解析、D3 力导向布局计算、数据预处理

- ✅ PIXI.js 可正常运行
- ✅ 调试方便 (独立 DevTools)

**缺点:**
- ❌ 额外进程开销 (~100-200MB 内存)
- ❌ IPC 通信比 Worker postMessage 慢
- ❌ 多进程管理复杂 (崩溃恢复、生命周期)
- ❌ 打包需处理多入口

**适用场景:** PlantUML、PIXI.js、需要 Node.js API 的渲染

```
┌─────────────────────────────────────────────────────────────────────┐

│                                 │          │          │        │   │
│                                 ▼          ▼          ▼        ▼   │
│                    ┌──────────────┐  ┌──────────┐  ┌──────┐  ┌──┐ │
│                    │ Worker Pool  │  │ 主线程   │  │ IPC  │  │..│ │
│                    │ (Mermaid/D3) │  │ (PIXI/  │  │(Plant│  │.│ │

│                           ▼               ▼           ▼      ▼   │
│                    ┌──────────────┐  ┌──────────┐  ┌──────┐     │
│                    │ SVG string   │  │ WebGL/   │  │ PNG/ │     │
│                    │ / coords     │  │ CSS anim │  │ SVG  │     │
│                    └──────┬───────┘  └────┬─────┘  └──┬───┘     │
│                           │               │           │          │
│                           ▼               ▼           ▼          │
│                    ┌──────────────────────────────────────────┐  │
│                    │           主线程渲染层 (统一)              │  │
│                    │  <svg v-html> / <canvas ref> / <div>     │  │
│                    └──────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

**调度策略:**

| 渲染类型 | 执行环境 | 理由 |
|---------|---------|------|
| **Mermaid** | Web Worker | 纯 JS 解析，输出 SVG string，Worker 完美适配 |
| **D3 布局计算** | Web Worker | 力导向迭代计算密集，DOM 更新回主线程 |
| **D3 DOM 更新** | 主线程 | 数据从 Worker 返回后，主线程批量更新 DOM |
| **PIXI.js** | 主线程 (独立 Canvas) | WebGL 需主线程，但独立 Canvas 不阻塞 Vue 渲染 |
| **PlantUML** | Python 后端 (IPC) | 需 Java 环境，Python 后端通过 child_process 调用 |
| **CSS 动画** | 主线程 (GPU) | `transform`/`opacity` 由 GPU 合成，不阻塞 JS |
| **SVG 静态图** | 主线程 | 直接 `v-html` 或 SVG 组件，无计算开销 |

## 三、架构决策

### 推荐: 方案 C (混合架构) + 统一 RenderManager

**核心理由:**

1. **没有单一方案能覆盖所有场景**
   - Web Worker 无法运行 PlantUML (Java) 和 PIXI.js (WebGL)
   - 独立渲染进程开销太大 (100-200MB)
   - PlantUML 放 Python 后端最合理 (已有进程)

2. **Electron 环境天然适合混合架构**
   - 主进程可管理 Worker + IPC + Python 后端
   - 渲染进程专注 UI，计算卸载到 Worker/后端

3. **统一 RenderManager 降低使用成本**
   - 组件层无需关心底层执行环境
   - `renderManager.render('mermaid', code)` 自动路由到 Worker
   - `renderManager.render('plantuml', code)` 自动路由到 Python 后端

### 4.2 RenderManager 核心设计

```typescript
// src/services/render-manager.ts

type RenderBackend = 'worker' | 'main-thread' | 'backend'

interface RenderConfig {
  backend: RenderBackend
  timeout: number
  cache: boolean
}

interface RenderTask {
  id: string
  type: RenderType
  data: any
  config: RenderConfig
  status: 'pending' | 'running' | 'done' | 'error'
  result?: any
  error?: string
}

class RenderManager {
  private worker: Worker | null = null
  private workerPool = new Map<string, Promise<any>>()
  private cache = new Map<string, any>()

  // 路由表
  private routes: Record<RenderType, RenderConfig> = {
    'mermaid':      { backend: 'worker', timeout: 10000, cache: true },
    'd3-layout':    { backend: 'worker', timeout: 5000,  cache: false },
    'plantuml':     { backend: 'backend', timeout: 30000, cache: true },
    'pixi':         { backend: 'main-thread', timeout: 0, cache: false },
    'css-animation':{ backend: 'main-thread', timeout: 0, cache: false },
  }

  async render(type: RenderType, data: any): Promise<RenderResult> {
    const cacheKey = `${type}:${hash(data)}`
    const config = this.routes[type]

    // 缓存命中
    if (config.cache && this.cache.has(cacheKey)) {
      return this.cache.get(cacheKey)
    }

    // 路由分发
    switch (config.backend) {
      case 'worker':
        return this.renderInWorker(type, data)
      case 'backend':
        return this.renderInBackend(type, data)
      case 'main-thread':
        return this.renderInMainThread(type, data)
    }
  }

  private async renderInWorker(type: RenderType, data: any): Promise<RenderResult> {
    // Worker 池管理，避免重复创建
    // postMessage + Transferable Objects
  }

  private async renderInBackend(type: RenderType, data: any): Promise<RenderResult> {
```

### 4.3 Worker 实现要点

```typescript
// src/workers/render-worker.ts

import { init as initMermaid, render as mermaidRender } from 'mermaid'
import * as d3 from 'd3'

// Worker 内初始化 Mermaid (独立配置)
initMermaid({
  startOnLoad: false,
  theme: 'dark',
  securityLevel: 'loose',
})

self.onmessage = async (e: MessageEvent) => {
  const { id, type, data } = e.data

  try {
    let result

    switch (type) {
      case 'mermaid':
        result = await renderMermaid(data)
        break
      case 'd3-layout':
        result = computeD3Layout(data)
        break
      default:
        throw new Error(`Unknown render type: ${type}`)
    }

    self.postMessage({ id, type, result })
  } catch (error) {
    self.postMessage({ id, type, error: error.message })
  }
}

async function renderMermaid(diagram: string) {
  const { svg } = await mermaidRender(`m${Date.now()}`, diagram)
  return { svg }
}

function computeD3Layout(graph: GraphData) {
  const simulation = d3.forceSimulation(graph.nodes)
    .force('link', d3.forceLink(graph.edges).id(d => d.id))
    .force('charge', d3.forceManyBody())
    .force('center', d3.forceCenter(500, 300))

  // 迭代 300 次后停止
  simulation.tick(300)

  return {
    nodes: graph.nodes.map(n => ({ id: n.id, x: n.x, y: n.y })),
    edges: graph.edges,
  }
}
```

## 七、结论

| 维度 | 评估 |
|------|------|
| **推荐方案** | **方案 C: 混合架构 + 统一 RenderManager** |
| **Worker 数量** | 1 个通用 Worker (Mermaid + D3)，非每个引擎独立 Worker |
| **PlantUML** | 放 Python 后端，不进入前端渲染管线 |
| **PIXI.js** | 主线程独立 Canvas，不阻塞 Vue 渲染 |
| **统一管理** | RenderManager 路由分发，组件层无感知 |
| **打包影响** | Worker 内联 (Vite 默认)，无额外体积 |
| **调试方案** | Worker 使用 `comlink` 库简化通信，Chrome DevTools Workers 面板 |

**核心理念: 计算与渲染分离**
- **计算** (布局/解析) → Web Worker
- **渲染** (DOM/WebGL) → 主线程
- **外部依赖** (Java/Python) → Python 后端
- **动画** (transform/opacity) → GPU 合成

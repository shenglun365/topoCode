## 2. 基础解析全流程

### 2.1 入口：`analyst_runner.py:_do_parse()`

运行在 `ThreadPoolExecutor(max_workers=4)` 的独立线程中，6 步串行执行：

```
_do_parse(task_id)
  │
  ├─ Step 1: AST 解析（并行）
  │   ├─ 按 scopes/extensions/exclude_dirs 过滤文件
  │   ├─ 按语言分组 files_by_lang
  │   ├─ ThreadPoolExecutor(PARSE_WORKERS=4) 并行解析
  │   └─ 写入 base_node 表
  │
  ├─ Step 2: 符号提取
  │   └─ extract_global_symbols(adapter) → graph_node 表
  │
  ├─ Step 3: 调用图提取
  │   └─ extract_call_graph(adapter) → graph_node 表 (call_relation)
  │
  ├─ Step 4: 依赖图提取
  │   └─ extract_dependency_graph(adapter) → graph_node 表 (include_relation)
  │
  ├─ Step 5: 社区分析
  │   ├─ analyze_communities(task_id, edge_type='INCLUDE') → graph_doc + community_hierarchy
  │   └─ analyze_communities(task_id, edge_type='CALL') → graph_doc + community_hierarchy
  │
  └─ Step 6: 结果汇总
      └─ upsert_report(report) → analysis_reports 表
```

### 2.2 Step 1: AST 解析

**文件**: `backend/parsers/parser.py:parse_file()`

```
parse_file(source_file_path, project_db, task_id, proj_path)
  │
  ├─ 1. detect_language(source_file_path) → 语言名
  ├─ 2. LanguageParserFactory.get_parser(language_name) → tree-sitter Parser
  ├─ 3. parser.parse(source_code) → AST Tree
  ├─ 4. get_language_config(lang) → LanguageConfig
  ├─ 5. 递归遍历 AST 节点
  │   ├─ 过滤 important_node_types
  │   ├─ 提取名称 (name_extract_rules)
  │   ├─ 计算 scope/parent 关系
  │   └─ 写入 base_node 表
  └─ 6. 返回节点数
```

**LanguageConfig 必须配置项**（每种语言各一份）:

| 配置项 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `important_node_types` | `Set[str]` | 需要存储的 AST 节点类型 | `{'function_declaration', 'class_declaration'}` |
| `is_name_node_types` | `Set[str]` | 直接作为名称的节点类型 | `{'identifier', 'field'}` |
| `scope_creating_types` | `Set[str]` | 创建作用域的节点类型 | `{'function_declaration', 'class_declaration'}` |
| `defining_context_types` | `Set[str]` | 定义上下文的节点类型 | `{'program', 'compilation_unit'}` |
| `node_type_to_op` | `Dict[str, str]` | 节点类型 → 操作符映射 | `{'binary_expression': 'op'}` |
| `name_extract_rules` | `Dict[str, List[str]]` | 节点类型 → 子节点类型优先级 | `{'function_declaration': ['identifier', 'function_name']}` |

### 2.3 Step 2: 符号提取

**文件**: `backend/parsers/extract_global_symbols.py`

```
extract_global_symbols(adapter)
  │
  ├─ 从 base_node 读取所有 AST 节点
  ├─ 按语言调用语言特定的符号提取规则
  ├─ 提取: 函数/类/方法/字段/接口/枚举/宏
  └─ 写入 graph_node 表 (symbol_node_type='func_name'/'class_name' 等)
```

### 2.4 Step 3: 调用图提取

**文件**: `backend/parsers/extract_call_graph.py`

```
extract_call_graph(adapter)
  │
  ├─ 从 base_node 读取所有 AST 节点，按 file_id 分组
  │
  ├─ 语言分发:
  │   ├─ Java → JavaCallGraphExtractor.extract(nodes_by_file)
  │   ├─ JavaScript → JavaScriptCallGraphExtractor.extract(nodes_by_file)
  │   ├─ TypeScript → TypeScriptCallGraphExtractor.extract(nodes_by_file)
  │   └─ 其他语言 → 通用调用图提取逻辑
  │
  └─ 写入 graph_node 表 (symbol_node_type='call_relation')
```

**调用关系节点字段**:

| 字段 | 说明 | 示例 |
|------|------|------|
| `caller_file_id` | 调用方 file_id (字符串) | `"file-0037e0c1c9e9"` |
| `caller_func_name` | 调用方函数名 | `"handle"` |
| `callee_file_id` | 被调用方 file_id (字符串) | `"file-abc123def456"` |
| `callee_name` | 被调用方函数名 | `"doHandle"` |
| `line` | 调用行号 | `42` |

### 2.5 Step 4: 依赖图提取

**文件**: `backend/parsers/extract_dependency_graph.py`

```
extract_dependency_graph(adapter)
  │
  ├─ 从 base_node 读取所有 AST 节点
  │
  ├─ 语言分发:
  │   ├─ 优先调用 extractor.extract_dependencies(nodes_by_file)
  │   │   ├─ Java → JavaDependenceExtractor.extract_dependencies()
  │   │   └─ 其他语言 → 通用逻辑
  │   │
  │   └─ 通用逻辑:
  │       ├─ _extract_dependency_target(node) → '.'.join(refs) (P0-1 已修复)
  │       └─ 写入 graph_node 表 (symbol_node_type='include_relation')
```

**依赖关系节点字段**:

| 字段 | 说明 | 示例 |
|------|------|------|
| `file_id` | 源文件 file_id | `"file-0037e0c1c9e9"` |
| `dependency_target` | 完整依赖路径 | `"org.springframework.beans.BeansException"` |
| `line` | 依赖行号 | `3` |

### 2.6 Step 5: 社区分析

**文件**: `backend/community_analysis.py:analyze_communities()`

```
analyze_communities(task_id, analysis_store, edge_type, min_node_cnt)
  │
  ├─ 从 graph_node 读取边 (CALL 或 INCLUDE)
  ├─ 构建无向图 (networkx)
  ├─ Louvain 算法 → 多层社区划分 (L0/L1/L2/L3)
  │
  ├─ 按 edge_type 处理节点:
  │   ├─ INCLUDE → aggregate_to_files() → 文件级社区
  │   └─ CALL → 保留函数级节点 (file_id:funcName)
  │
  ├─ 写入 graph_doc 表 (node_list, edge_list, quality 等)
  └─ 写入 community_hierarchy 表 (parent_comm_id, level)
```

## 3. LLM 解析全流程

### 3.1 触发条件

用户在报告页面点击 **"AI分析"** 快捷按钮，触发 `LLMChatFlow.vue` 中的 `onQuickParseCommunity()`。

### 3.2 数据流

```
前端 LLMChatFlow.vue
  │
  ├─ 1. 用户点击 "AI分析" 按钮
  │   └─ onQuickParseCommunity(templateId='community_explain')
  │
  ├─ 2. buildCommunityData(graphData) → 组装变量
  │   ├─ commId: 选中社区 ID
  │   ├─ nodeCount/edgeCount: 统计
  │   ├─ nodeList: 节点列表 (前50个, "- label [ref:xxx, file:xxx]")
  │   └─ edgeList: 边列表 (前50个, "- source -[调用]→ target")
  │
  ├─ 3. window.api.llm.chat({
  │       sessionId: '_inline_${Date.now()}',
  │       modelId: settingsStore.defaultModelId,
  │       templateId: 'community_explain',
  │       variables: commData,
  │       mode: 'chat'
  │     })
  │
  └─ 4. 订阅流式响应
      └─ window.api.llm.subscribe(requestId, {onChunk, onDone, onError})
```

```
后端 llm_service.py:chat()
  │
  ├─ 1. PromptManager.render(templateId, variables)
  │   ├─ 读取 llm_prompt_templates 表
  │   ├─ 替换 {variable} 占位符
  │   └─ 返回 messages=[{role:'system', content:...}, {role:'user', content:...}]
  │
  ├─ 2. LLMService.streaming_chat(sessionId, messages, model, mode)
  │   ├─ 获取模型配置 (API key, base_url, model name)
  │   ├─ 启动 HTTP streaming 线程
  │   ├─ 批处理 chunk (100ms/200字符)
  │   └─ ZMQ PUB 推送 chunk 事件
  │
  └─ 3. _save_streaming_messages(sessionId, fullContent)
      ├─ 自动创建 session (llm_sessions 表)
      ├─ 保存 assistant 消息 (llm_messages 表)
      └─ 记录调用日志 (llm_call_logs 表)
```

### 3.4 LLM 三种模式

| 模式 | 说明 | 特点 |
|------|------|------|
| `chat` | 对话模式 | 完整文本流式输出 |
| `tools` | Tools Calling | 模型按需调用工具（get_file_content, get_symbol_detail 等），最多 5 轮 |
| `structured` | 结构化输出 | JSON Schema 校验，失败自动重试 2 次 |

| `llm_sessions` | 会话库 | session 元数据 (id, module_type, title, status) |

| `llm_call_logs` | 主库 | 调用日志 (model_id, provider, mode, status, duration) |
| `llm_prompt_templates` | 主库 | Prompt 模板 (id, name, system_prompt, user_prompt_template) |

class CallGraphExtractor:

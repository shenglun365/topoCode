# 编排 v2 改造计划 —— 交接切面 · 挡位总控 · 里程碑协议

> 定位: 本文档是 orchestrator v2 系列环节(十一~十五)的总体设计与实施顺序。
> 来源: cv-173/176/179 三次任务失败实证 + 交接切面专题讨论定论。
> 每个环节独立提交, 落地时以本文档为唯一计划真相源; 偏离需回写本文档。

## 0. 设计原则(讨论定论, 全环节遵守)

1. **任务卡 = 交接切面**: architect↔subagent 的工作交接界面, 非软件工程规格文档。
   最小完备集五要素: 目标 / 边界(文件级) / 完成判据(DoD) / 连续性(续跑上下文) / 反馈通道(waiting_input)。
2. **有效性 = 文件状态**: 一切有效性判定以 git 文件状态为准(存在性/diff/commit),
   不做 AST/语义解析, 不做 architect 侧语义验证(构建+冒烟足够)。
3. **职责分层**: inter-task 拆分归 architect(KB+资产 grounding); intra-task 拆分归
   subagent(代码探索事实)。两层互相供数(里程碑报告回写边界 → 后续任务先验更准)。
4. **策略数据驱动**: 挡位 = 策略表的一行, 不是代码分支。解析一次 → policy 对象
   逐层传递, 禁止 `if tier == "T2"` 散落各处。
5. **护栏执行器无关**: 循环检测器等护栏在 runner 基座/共享模块实现,
   三个执行器(cline/opencode/codex)同一套; 事件粒度不足时优雅降级。
6. **不建清单**(负空间): AST 解析 / 形式化验收矩阵 / 追溯链 / 细规格微观管理 /
   逐步 hash 校验(worktree 独占使其冗余) / 模型能力自动评分以外的花活。
7. **失效代码即拆**: 不做兼容旧逻辑; 每环节提交包含该环节产生的移除项。

## 1. 目标架构分层

```
┌─ architect 总控层 ────────────────────────────────────────┐
│ 需求 → 任务计划(范围探针 grounding, 挡位定粒度)            │
│ 分批下发(顺序默认/边界不相交才并行) · 汇总验收             │
├─ subagent 执行层 ─────────────────────────────────────────┤
│ 探索 → [计划确认] → 里程碑N(实现→验证→自动commit→等指示)×  │
│ 护栏: 轮次上限(挡位) + 三类循环检测器 + 停滞看门狗          │
├─ 交接切面层(文件状态) ────────────────────────────────────┤
│ 创建/里程碑/合并 三边界快照 · waiting_input 双向管道        │
└───────────────────────────────────────────────────────────┘
```

数据流: 需求文本 → 范围探针(文件树+任务历史+KB) → 任务卡(边界带引用) →
subagent 里程碑报告 → 回写需求边界 → 下一任务/批次先验增强(自我修正闭环)。

## 2. 环节分解

### 环节十一: 里程碑协议 + 循环护栏(核心地基, 最先做)

> **状态: 已落地**。as-built 修正: 无进展看门狗的信号从"porcelain 哈希"细化为
> **tracked 文件内容哈希 + untracked(路径,大小)清单**复合信号(porcelain 只记
> 状态行不记内容, 同文件反复编辑不会变——会误伤编辑-编译循环);
> 顺带修复存量 bug: `base="HEAD"` 字面量在自动 commit 后导致 diff 恒空,
> 已在 ImplementJob 构造时钉死为具体 SHA, `_diff_files` 改为对基点的
> name-only diff。

**目标**: 长任务从"单回合跑到死"变为"探索→计划确认→里程碑序列(每里程碑等指示)";
轮次放大到 2000 的同时用循环检测器防异常浪费。

**内容**:
1. **协议文本**(prompts.py 任务指令模板追加, 单源):
   - 复杂任务先探索, 首个回复提交**里程碑计划**(按功能模块+可独立验证标准划分), 等待确认;
   - 每个里程碑完成: 发里程碑报告(固定行格式 `改动文件: ...` + `commit: ...` +
     `验证: ...`)并等待指示; 禁止未报告跨里程碑;
   - "可单元测试"是**拆分粒度标准**(里程碑可独立验证), DoD 仍是构建+运行冒烟,
     单测为 subagent 自主选用手段, 非 architect 门禁。
2. **里程碑报告渲染**: waiting_input 回执在任务卡/会话流展示报告;
   `改动文件:` 行宽松解析 → **回写需求 allowedScope**(自我修正闭环的落点)。
3. **baseCommit 快照**: 任务创建时记录 worktree HEAD(交接边界快照之一,
   供十五合并检查与回写比对)。
4. **轮次上限**: 120 → 2000(registry 默认; 后续按挡位取值)。
5. **三类循环检测器**(共享模块 `runner/loopguard.py`, 挂适配器事件泵):
   - 重复指纹: `hash(tool+参数+输出摘要)` 连续 ≥3 相同 → 中止;
   - 无进展看门狗: 每 20 轮比对 `git status --porcelain` 哈希, 连续 3 次不变
     且无 pending input → 中止(回合级, implement.py 作业循环);
   - 错误签名: 同错误文本哈希 ≥5 次 → 中止;
   - 触发 → 进度 commit(已有) → failed 回执带诊断(指纹/计数),
     用户调整上下文后续跑。
6. **检测器降级**: opencode/codex 事件粒度不足时仅无进展看门狗生效(回合级)。

**依赖**: 现有 waiting_input/泵/进度 commit/续跑/事件环, 全部复用, 零新协议。
**移除**: registry `max_iterations=120` 硬编码与相关注释。
**验收**: 伪适配器里程碑流程 e2e 测试(计划确认→里程碑→继续); 三检测器单测;
全量门禁。

### 环节十二a: 挡位体系(策略表 + 解析链 + 模板分叉)

> **状态: 已落地**。as-built: 挡位指引合并进 orchestrator 单条系统消息
> (废除 prompt.gear_guidance 二值文本与独立注入); req_agent 死常量
> (_QUICK_DENY_TOOLS/_QUICK_KB_PREFIXES)拆除——挡位行为差异全部走提示词面;
> strict/quick 前端线协议值保持不变(quick→T0, strict→auto 服务端映射)。

**目标**: 现有 quick/strict 二值升级为 T0-T4 连续挡位, 策略数据驱动。

**策略表**(`agent/governance/gears.py`, 新模块):

| 档 | 语义 | KB/探针 | architect 预拆 | 确认节奏 | 轮次/卡 |
|----|------|---------|----------------|----------|---------|
| T0 | 强模型直通车(=现 quick) | 关 | 无(subagent 自拆) | 计划+每里程碑 | 2000 |
| T1 | 强模型+资产 grounding | 开 | 无 | 计划+每里程碑 | 2000 |
| T2 | 中模型任务级预拆 | 开 | 任务计划(多卡) | 每卡+每里程碑 | 800 |
| T3 | 弱模型步骤级编排 | 开 | 卡+显式文件路径+步骤序列 | +关键步 | 300 |
| T4 | 微步确认 | 开 | 微步拆分 | 每步 | 100 |

**解析链**: 会话 `analysisMode`(`quick`|`auto`|`T0`-`T4`) → auto 时
实测档位(十二b) > 执行器配置 `capability` 字段 > 默认 T1。
解析一次得到 Policy 对象传给指令模板/轮次/确认节奏, 全程无散落分支。

**内容**: 策略表数据 + resolve 函数 + sessions.py mode 白名单扩展 +
prompts.py `build_task_instruction(policy, ...)` 按挡分叉(粒度提示/步骤提示/
轮次注入) + 执行器配置 `capability` 字段(写侧校验) + 前端闪电钮语义升级
(T0/auto, 文案更新) + 执行器配置面板挡位选择。

**依赖**: 十一(确认节奏/轮次由协议文本承载)。
**移除**: orchestrator/commands 中 `analysis_mode=="quick"` 旧二值特判分支;
prompts.py 被分叉取代的单一 DoD 常量; 前端 quick/strict 旧文案。
**验收**: resolve 链单测(各级覆盖) ; 模板分叉快照测试; 门禁。

### 环节十二b: 能力探测(测试用例 + 评估算法)

> **状态: 已落地**。as-built: 探针为 python 自包含夹具(pytest 判分, 仓库带
> .gitignore 防 pycache 误判); REST 为 POST/GET
> `/agent/executors/{id}/capability-probe`(异步后台+内存运行守卫, 结果落注册表
> config); needsReprobe=探测后 model_id 已变更; 引擎轮询计数 tool 事件作迭代
> 效率分母。

**目标**: 执行器实测档位, 替代人工猜 `capability`。

**探针套件**(5 个标定任务, 沙箱 git 仓库, 与项目代码无关, 走真实 turn_adapter
管道——测模型+执行器+适配器整栈):

| # | 探针 | 测什么 | 确定性判分 |
|---|------|--------|-----------|
| 1 | 按给定测试集写实现 | 编码正确性 | 测试全过 |
| 2 | 修复种子 bug | 调试 | 测试转绿 |
| 3 | 行为保持重构 | 约束遵循 | 仍绿+diff 在边界内 |
| 4 | 多步精确指令跟随 | 指令遵循(弱模型短板) | 产物文件+内容谓词+禁副作用核验 |
| 5 | 跨文件小功能 | 探索+集成 | 构建+集成测试 |

**评估算法**(无 LLM judge):
`探针得分 = pass × 迭代效率(实际/预算) × 边界遵守(越界写→×0)`;
`综合分 = Σ wᵢ·探针ᵢ`(指令跟随 0.3 > 编码 0.25 > 调试 0.2 > 集成 0.15 > 重构 0.1);
阈值映射档位; **探针 4 否决**: 不过 → 最高 T3。

**存储**: 执行器配置 `{tierProbed, score, detail, probedAt}`; REST
`/executors/{id}/probe`; UI 配置面板"探测能力" + "实测 T2 (4/5)"展示;
模型配置变更提示重测。

**依赖**: 十二a(档位字段落位), runner 管道(已有)。
**移除**: 无。
**验收**: 探针判分器单测(固定 fixture); 评分映射单测; 门禁。

### 环节十三: 范围探针(KB+资产 grounding) + 边界缺省保护

> **状态: 已落地**。as-built: 探针仅在**边界为空时**触发(有边界不重复探,
> 省 LLM 时间且避免噪声); 续跑过期提示挂在 propose 任务卡(非阻断),
> 空边界警示挂卡片(确认=显式接受); 顺手修两处存量缺陷——
> propose_task 收到的 conv 可能是 create() 返回值(缺 reqId 字段)→ 入口重取
> 全量行; arch_tasks.base_commit 需主库+项目库双迁移 + TasksStore.create
> 白名单补字段。

**目标**: allowedScope 不再靠需求文本盲猜; 空边界不再等于无保护。

**内容**:
1. `probe_scope(需求文本, KB命中, 任务历史, 文件树)` → `{files, sources}`:
   单次 LLM 调用, **要求带引用**(来源: tree/history/kb/milestone-report);
   grounding 数据全部已有(arch_tasks 边界+diff 统计, KB 工具, 文件树)。
2. **空边界保护**(吸收原环节十): 探针结果为空 → 回执明确标注"无互斥保护"
   并要求显式确认; 创建时边界文件存在性检查(`git ls-files`,
   不存在须声明"新建")。
3. `governance/boundary.py` 扩为文件状态助手单源: 存在性检查 /
   `changed_since(commit, files)`(供交接前过期判定) / files_intersect(已有)。
4. 需求**过期提示**(吸收原环节九简化版): 执行/续跑前
   `changed_since(baseCommit, 边界文件)` → 变了 = 交接过期, 提示重新交接
   而非盲目续跑。这是"腐烂需求"的可操作定义(git 事实, 非 TTL)。

**依赖**: 十一(里程碑回写数据), KB 工具(已有)。
**移除**: propose_task 内旧的边界建议逻辑(若有)。
**验收**: 探针 prompt 快照测试; changed_since/存在性单测; 空边界确认流测试。

### 环节十四: 任务计划 + 分批下发总控

> **状态: 已落地**。as-built: 计划存需求行 `taskPlan` JSON 列(主/项目库双迁移,
> 注册 _JSON_COLUMNS 解析); 拆步 LLM 仅 T2+ 挡位(pre_split≠none)且 ≥2 步才成计划,
> 单步回落原单卡路径; done/failed 事件钩子驱动"预填下一步/步骤重发/汇总回执";
> 跨会话并行天然由既有 check_mutex 兜底(同会话单活跃任务互斥不变),
> 不做自动并行调度。taskPlan/taskPlanDone 卡以 markdown 文本落流(词汇表已注册)。

**目标**: 需求 → 多任务卡编排 → 有序下发 → 汇总验收(最小可行, 不做 DAG PM 系统)。

**内容**:
1. **任务计划**: 需求上存 `plan: [{seq, title, boundary, depends}]`
   (architect LLM 生成, 范围探针 grounding, T2+ 挡位才启用预拆);
   卡片词汇表 `cards.py` 增加 `taskPlan` 种类; 用户**一次确认**整计划。
2. **顺序下发(默认)**: 任务 N done → 下一卡自动预填(含任务 N 成果摘要+边界)→
   确认 → 执行。
3. **并行下发(可选)**: 仅当边界不相交——confirm 前逐卡调 `check_mutex`
   (已有, 零新隔离机制)。
4. **汇总验收**: 全部 done → 汇总回执(各任务 diff 统计) + 合并提醒。

**依赖**: 十一(里程碑), 十二a(T2+ 才预拆), 十三(范围)。
**移除**: 无(计划复用任务卡全链路)。
**验收**: 计划生成/预填/互斥拦截单测; taskPlan 卡渲染 vitest。

### 环节十五: 回退消息 + 合并入口 hash 检查(收尾, 可与十二b 并行)

> **状态: 已落地**。as-built: 回退 = DELETE
> `/requirements/conversations/{id}/messages/{msgId}/after`(time+rowid 排序
> 语义与 messages() 一致, 运行中任务 409 守卫, 前端消息行内回退按钮 →
> conversation-store.rollbackTo 本地截断); 合并入口 = GET
> `/tasks/{id}/merge-precheck`(fastForward/mainNewCommits/branchCommits/
> advice), done 卡"合并检查"按钮 → 轻提示。

**目标**: "停止→调整上下文→再执行"补齐最后缺口; 合并时刻的安全检查。

**内容**:
1. **回退到消息 N**: REST `DELETE /sessions/{id}/messages-after/{msgId}`
   (截断其后全部, 非任意删改——回退点后语义作废, 干净);
   前端消息菜单"回退到此"; 运行中任务须先停止(守卫);
   会话 reqId 绑定保留, 任务回执存于任务库不受影响。
2. **合并入口检查**: `GET /tasks/{id}/merge-precheck` → 主目录 HEAD vs
   任务 baseCommit(十一记录); 变了 → 列出期间提交+提示先 rebase/冲突检测;
   done 卡加"合并检查"按钮。git 三方合并本身即 hash 校验, 我们守入口。

**依赖**: 十一(baseCommit); 回退依赖会话存储(已有)。
**移除**: 无。
**验收**: 回退截断/守卫单测; merge-precheck 单测(变/未变/无 baseCommit)。

## 3. 依赖关系与实施顺序

```
十一 里程碑协议+护栏 ──┬──→ 十二a 挡位体系 ──→ 十二b 能力探测
                      ├──→ 十三 范围探针 ──→ 十四 任务计划总控
                      └──→ 十五回退+合并检查(独立, 可与十二b 并行)
```

**顺序**: 十一 → 十二a → 十二b → 十三 → 十四 → 十五。
理由: 协议是地基(确认节奏/轮次/报告由它承载); 挡位是协议的参数化;
探测校准挡位; 范围探针需要回写数据积累; 总控需要范围+挡位; 收尾独立。

**规模预估**: 十一 大(2-3 commits) / 十二a 中 / 十二b 中 / 十三 中 / 十四 大 / 十五 小。

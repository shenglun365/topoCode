# 意图空间一期：两线互通 × Skill Runner × 契约事实化 × 解读回环

> 定稿 2026-10-09（三轮架构讨论 + 六项决策）。交付：B1 `160e80a8` / A2 `fcfce2b8` /

## 1. 背景与业务目标

开发者工作环（认知-行动闭环）：

```
代码(L0 锚点) → 语义理解(L1) → 意图表达(L2) → 方案执行(L3) → 变更反馈(L4) → 回写认知
```

L0→L1 与 L2→L3 建设已有积累；本期补两个衔接断点：

- **下行断点（L1→L2）**：理解系统之后，表达出口接近白纸——语义资产未转化为
  意图草稿素材；小问题被迫走重流程。
- **上行断点（L3→L4）**：变更反馈停留在文件层，无验收↔方案回指与语义回执
  （二期）。

两项立场所属决策：

| 决策项 | 裁决 |
|---|---|
| 推进顺序 | 意图空间统一 → skill 体系 → 上行反馈 |
| skill 承载 | 统一 runner 两线暴露（草稿线/会话线） |
| 引导时机 | 上下文感知建议（提示不拦截） |
| 解读回环开启 | 按任务挡位默认（high-stakes 开），任务卡可手动开关 |
| 解读校验裁决 | 规则可判自动；语义偏差出建议、用户终裁 |
| 事实化装配存量 | 下发时动态装配，不回填历史规约 |

## 2. 架构总图

```
                    ┌─────── 意图空间(两线一底座) ───────┐
   资产选区引用 ──→ │ 草稿线(文档态) ⇄ 会话线(对话态)     │
   (draft-ref-bus)  │ publish→ / ←save-draft 另存回流     │
                    └──────────┬─────────────────────────┘
                    Skill Runner(统一注册表, 两线暴露, 上下文感知建议)
                               │ 下发装配: 三通道分层(事实/意图/推断)+冲突约定
                               ▼
                    解读回环(先解读后开工→规则校验→人工放行/纠偏) → 执行器(自主性不设限)
```

两线本质同源（意图的文档态/对话态），下游执行共享；草稿与规约为同一演进轴
（草稿→规约快照版本链→任务契约）。

## 3. 交付明细

### B1 统一 Skill Runner（`agent/skills.py` + `req_drafts.py` 泛化）

- SkillSpec 注册表单源：`{id/指令/工具白名单/线域/系统提示}`；首批
  generate/review/relate（自 `_PRESETS` 行为等价迁移）。
- 作业类型 `skill_run`（`draft_ai` 存量别名同执行体）；`topo-skill:<id>` 围栏
  技能直呼（与 `topo-cmd` 共解析，未注册 id 不虚构）。
- `POST /req-drafts/{id}/ai` 增 `skill` 字段（preset 兼容）；`GET /skills`。

### A2 会话→草稿回流

- `arch_req_drafts` 增 `source_conv_id/source_kind`（turn|spec|receipt），
  续写副本继承溯源。
- 会话消息操作区「另存为草稿」；DraftDock 列表来源 chip。
- 闭环：会话回合 → 草稿（技能加工）→ publish 回会话（amend/propose 既有）。

### C3 缺口建议 + 三通道事实化装配

- **三通道**（`context_pack.py`）：意图通道（需求原文「用户意图」节）/推断通道
  （designMd「架构师推断——以代码为准」头注，图邻域同措辞）分节；allowedScope
  标注「语义别名」/边界文件标注「代码坐标」；冲突约定总则随行（**描述与代码
  冲突以代码为准，冲突点在解读环节提出——执行器被授权质疑描述**）；slim 版同附。
- **缺口检测**：`GET /req-drafts/{id}/gaps`（规则版：过短→generate/缺验收→
  review/未关联→relate）+ DraftDock 建议条（chips 一键调技能，可关闭）；
  `GET /sessions/{id}/spec-gaps`（gap_matrix 单源）+ dock 工具栏缺口 chip。

### D4 解读回环（`agent/execution/readback.py`，零 runner 协议改动）

- 指令注入「开工前解读」段：执行器首回合输出**我的理解**（目标复述/代码坐标/
  计划要点/冲突点/疑问）并主动 WAIT。
- 规则校验（input_required 首次到达）：代码坐标对账（相等/目录前缀=界内）+
  验收呼应（条目关键词过半出现，中文 2-gram）；建议附注落卡，`progress
  .readbackDone` 一次循环不往复；**偏差人工终裁**（放行=回复确认，纠偏=指出问题）。
- 开启：`readback_enabled`（high-stakes 挡位默认开，`task.readback` on/off
  显式覆盖）；arch_tasks 增列；`POST /tasks/{id}/readback` + TaskCard 开关。

## 4. 边界（明确不做）

表单模板/schema 强填；建议拦截发布；规约数据模型与 publish 语义变更；
低质量契约硬拦；步骤级硬编排（检查点不是脚本——「做什么」受约束，「怎么做」
完全开放）。

## 5. 二期预告

1. **技能族扩展**：方案骨架（资产锚定起稿）/验收提炼（可测性分级+verifyConfig
   映射建议）/边界圈定（图邻域建议 scope）/节点切分（里程碑检查点）。
2. **上行线（L3→L4）**：变更回执语义化（验收逐条对照+受影响资产+结论评估，
   人工裁决）+ 图谱增量更新（认知回写）。
3. **解读校验 LLM 增强**：语义偏差评估建议（规则版之上）；任务卡关键节点回执。
4. 会话线技能装配器（runner 会话域上下文：规约快照+选定回合）。

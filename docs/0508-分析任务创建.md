# 分析任务创建 — 设计方案

> 日期: 2026-05-08 | 状态: 待确认

---

## 一、需求概述

在项目视图中提供**解析设置**入口，支持在当前项目的 Tab 栏内管理分析任务（列表查看 / 新建任务），新建任务时提供文件类型统计辅助面板帮助用户精准设定分析范围。

---

## 二、交互流程

```
进入项目视图
  │
  ├─ 点击标题栏「解析设置」按钮
  │   └─ 打开「任务列表」Tab（若已存在则直接激活）
  │       │
  │       ├─ 展示当前项目已有任务列表（状态/进度/执行结果）
  │       └─ 点击「+ 新建任务」
  │           └─ 打开「新建任务」Tab
  │               │
  │               ├─ 左侧: 文件分布统计辅助面板
  │               └─ 右侧: 任务配置表单
  │                   └─ 提交 → 创建任务 → 关闭新建 Tab → 刷新任务列表
  │
  └─ 点击左侧文件树中的文件
      └─ 打开文件 Tab → CodeViewer 渲染
```

#### 4.2.2 任务操作按钮

每个任务卡片提供以下操作按钮，根据任务状态动态显示：

| 按钮 | 状态条件 | 功能说明 |
|------|----------|----------|
| **查看详情** | 所有状态 | 弹出任务详情面板，展示完整执行日志、进度历史、报告摘要 |
| **停止** | `running` | 终止正在运行的任务，状态变为 `stopped` |
| **重跑** | `done`, `error`, `stopped` | 使用原任务配置重新执行，生成新的执行记录 |
| **重试** | `error` | 等价于重跑，语义上强调"从失败恢复" |
| **编辑** | `pending`, `done`, `error`, `stopped` | 打开 TaskCreateForm Tab，预填原任务配置，允许修改后保存 |
| **删除** | `pending`, `done`, `error`, `stopped` | 弹出确认对话框，确认后删除任务及其关联报告数据 |

> 注意：`running` 状态的任务不允许编辑和删除。

## 五、数据源 — SQLite source_files 表

### 5.1 数据来源

**从 SQLite 读取，不扫描文件系统。** 项目导入时已将所有文件信息写入 `source_files` 表：

```sql
CREATE TABLE source_files (
    id TEXT PRIMARY KEY,
    file_path TEXT NOT NULL UNIQUE,    -- 相对路径
    language TEXT,                      -- 语言类型
    size INTEGER DEFAULT 0,            -- 文件大小
    content_hash TEXT,                  -- 内容哈希
    parent_path TEXT,                   -- 父目录路径
    created_at TEXT,
    updated_at TEXT
);
CREATE INDEX idx_source_files_parent ON source_files(parent_path);
```

### 5.2 统计 SQL

```sql
-- 按语言分组统计
SELECT language, COUNT(*) as count, SUM(size) as total_size
FROM source_files
WHERE file_path LIKE ?                  -- 目录范围
  AND file_path NOT LIKE ?              -- 排除目录
GROUP BY language
ORDER BY count DESC;

-- 提取目录列表（供下拉选择）
SELECT DISTINCT parent_path
FROM source_files
ORDER BY parent_path;

-- 总文件数 / 总目录数
SELECT COUNT(*) FROM source_files WHERE ...;
SELECT COUNT(DISTINCT parent_path) FROM source_files WHERE ...;
```

### 5.3 正则匹配处理

SQLite 不支持正则表达式，因此 `pattern_type === 'regex'` 时：
1. 先从 SQLite 取出所有 `file_path`
2. 在 Python 层用 `re.match()` 过滤
3. 再对过滤结果做分组统计

```typescript
const fileStatsCache = ref<Map<string, FileStatsResult>>(new Map())

async function scanFileStats(projectId: string, options?: ScanOptions) {
  const cacheKey = JSON.stringify({ projectId, ...options })
  if (fileStatsCache.value.has(cacheKey)) {
    return fileStatsCache.value.get(cacheKey)!
  }
  const result = await ipc.analysis.scanFileStats(projectId, options)
  fileStatsCache.value.set(cacheKey, result)
  return result
}
```

```typescript
function openTaskListTab() {
  // 若已存在 taskList tab，直接激活
```

## 十、匹配模式说明

| 模式类型 | 输入示例 | 匹配效果 | 后端处理 |
|----------|----------|----------|----------|
| 全部文件 | (空) | 扫描所有已导入文件 | 无 WHERE 过滤 |
| 字符串匹配 | `src/**` | `src/` 下所有文件 | `file_path LIKE 'src/%'` |
| 字符串匹配 | `*test*` | 路径含 `test` 的文件 | `file_path LIKE '%test%'` |
| 正则表达式 | `^src/(lib|core)/.*\.py$` | `src/lib/` 和 `src/core/` 下的 `.py` | 取全部路径 → `re.match()` |
| 正则表达式 | `^(?!.*node_modules).*$` | 排除 `node_modules` | 同上 |

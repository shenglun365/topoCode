# Architect 重建 · 界面变化明细（Plan C 配套）

> 版本 v1.6 | 日期 2026-08-30 | 配套主文档：`plan-C.md`（v1.7，M1+M2+M3 前端已落地）
> 本文档只描述**本次改版后 architect 前端界面**的变化（before → after），不含后端/schema/协议（见 plan-C）。
> 原则贯穿：architect 不决策 → 界面上所有"判定/通过/打回/确认"动作都归于设计者；事实与参考意见双通道呈现；覆盖度诚实；按需提取。
> v1.1 变更（需求方界面决议）：① 需求方案组三菜单保留（单元测试新增局部验收）；② 框架标准选择（高/中/低预设+自建）落**资产概览 tab**，标准变更→资产整体作废+命名不继承；③ **语义资产与组件资产 tab 合并**（组件树挂资产，多归属重复显示，"其它"组保留）；④ 语义图谱**不冻结**（双图对照/轴过滤/覆盖度保留）；⑤ 局部验收→单元测试页，整体基线变更分析→影响分析（archmap?view=impact）；⑥ 命名规约/术语表落**项目规约页**（场景标签，agent 按场景加载）。
> v1.2 变更（开发前核查修正）：§2.0a 补对话区内嵌全量提取按钮（易漏的第二处全量入口）；§2.2 补 INCLUDE/CALL 口径筛选；§6 补实现载体 SpecWorkspace.vue；§8 局部验收挂载位描述改准确（会话 tab 制）。
> v1.3 变更（M0 评审决议同步）：§5.1 L3 改为**人工主判 + 条目行「激活模型辅助」按钮按需触发**（无自动抽样）；§4 差异报告卡概览改"L1/L2 通过率 + L3 待人工数"；§9 M2 补 L3 按需激活入口。
> v1.4 变更（M1 前端落地 + 实现修正）：§2.0a 两处全量入口已按方案退役（bundle `architect.CcPMBPq6.js`）；§2.1 框架面板/覆盖度面板已实现（preview→confirm→switch 确认流）；§2.2 tab 合并落地，**修正**：INCLUDE/CALL 与 L0/L1 组件口径筛选在合并 tab 无实际作用，按如实原则移除（保留 compLevelSel 层级起点筛选），§1/§9 对应更新。
> v1.5 变更（M2 前端落地，bundle `architect.BlnwQx3G.js`）：§4 **契约条目固化卡**已实现（方案对话 🧾 开关 + 逐条 确认/修改/删，仅 draft 可操作，判定统一在验收区块）；§4 **需求详情契约条目只读区**已实现（需求池卡片内展开，状态机展示）；§8 **局部验收区块挂载位定稿 = 单元测试页独立固定 tab「局部验收」**（`AcceptancePanel`：契约包选择 + 触发验收 + 报告展开 L1/L2 事实徽标/证据 + 设计者通过/打回 + 激活 L3 参考意见 + 修复指令草稿复制）；§4 差异报告通知卡（对话内）顺延 M2 剩余（验收区块已承载判定动作，通知卡为增强项）。
> v1.6 变更（M3 前端落地，bundle `architect.CpYOVqb3.js`）：§6 **项目规约页新增「命名规约」tab**（`NamingGovernancePanel` 三子 tab：命名规约——新增/场景标签多选/pending 归纳提案确认/停用启用/删除；术语表——搜索/新增/文档导入/删除；命名历史——墓碑参考池搜索）；§2.2 **语义资产行内改名**（铅笔→inline 输入→确认/取消；main-KB 关联项目后端 409 拒绝并提示深链）；§9 M3 对应行更新。

### 2.1 概览 tab（认知框架管理 + 覆盖度）

| 区块 | 改版前 | 改版后 |
|---|---|---|
| 统计卡 | 总量/按类别/按粒度/状态 | 保留 |
| [新增] 框架标准选择 | — | **高 / 中 / 低 三组默认元认知分类标准**（每组 = 分类值域 + 抽象粒度组合，清单综合 plan-A/B/C 三档定义，M0 固化）+ **自建框架入口**（高级：轴/值域编辑器）。当前框架版本/档位一目了然 |
| [新增] 标准变更确认流 | — | 切换标准 → 弹影响范围（"N 个资产将作废、命名不迁移"）→ 设计者确认 → 执行。**标准变更 ≠ 代码变更**：前者资产整体作废+命名继承中断；后者走 stale/墓碑/命名继承（详见 plan-C §3.2）。主 KB 模式下此操作收口主 KB 界面 |
| [新增] 覆盖度 | — | `已提取 n / 覆盖组件 m / 过期 k`，悬停列出"从未提取的组件/文件"；标准变更后空窗如实显示 |

### 2.2 语义资产 tab（语义 + 组件合并：组件树挂资产）

组件树为骨架、语义资产挂在所属组件下方（按组件层级缩进）：

| 区块 | 内容 |
|---|---|
| 组件行 | **保留原有元数据**（owns 文件、dependsOn、change 状态、L0/L1 层级）+ 资产覆盖状态徽标 + 「对话提取」入口（预填消息到右栏） |
| 资产行（缩进挂组件下） | 名称 + 来源徽标（用户/规约/LLM）+ 类别/粒度（读框架配置）+ 结构摘要 chips（`5字段·6步·2分支·3关系`）+ 过期/失效/未锚定状态 |
| 多归属 | 共享资产（INCLUDE/CALL 双组件拥有）**允许在多个组件下重复显示**（既有 componentsOf 机制） |
| 「其它」组 | 未归属任何组件的资产保留该组 |
| 展开详情 | fields/steps/branches + 伪码解释 + **命名历史**（当前名+历史名+来源+时间，失效名灰显"参考"） |
| 行尾操作 | 刷新 / 问 agent / 对话提取 |

过滤器：类别/粒度下拉读框架配置（档位裁剪后只显示启用值域）；组件层级起点筛选（L0/L1，compLevelSel）沿用。~~INCLUDE/CALL 口径与 compLevel 筛选~~——合并 tab 无实际作用，**已移除**（如实原则，v1.4 修正）。

### 2.3 资产管理操作（改名 / 合并 / 拆分）

单机模式（无主 KB）：
- **改名**：详情面板内联改名（只动认知层，锚点不动）；违反规约黄色提示不阻止；写入命名历史。**仅在当前标准生命周期内有效**——标准变更后命名整体作废、不迁移。
- **合并**：多选 → 确认弹窗（目标名、锚点并集预览、detail 冲突标记、关系重定向说明）→ 执行留审计。
- **拆分**：agent 提案划分方案（锚点/步骤归哪个新资产）→ 设计者调整 → 确认。

主 KB 模式：上述操作**按钮变灰并跳转主 KB 编辑台**（见 §6.3），agent 可代填提案后深链。

## 3. 语义图谱（SemanticGraphView）——不冻结，增量增强

> 需求方确认：图谱**不冻结**，此前"基本保持不变"表述不准确。以下增强保留。

| 能力 | 改版前 | 改版后 |
|---|---|---|
| 过滤 | 类别/粒度下拉（硬编码） | 下拉改读框架配置；**新增轴过滤条**：自定义轴/值域作为标签过滤（只影响显示，不生成视图） |
| 覆盖度 | 无 | **覆盖度图层**：未提取组件/文件灰化或虚线框；过期资产红色描边（可开关） |
| 期望 vs 实际 | 无 | **双图对照模式**：L2 行为比对时并排渲染"期望子图（契约条目）"与"实际子图（提取资产）"，差异边/缺失节点高亮（差异点点击 → 差异详情；报告主体与判定动作在单元测试页局部验收区块 §5.1） |
| 节点信息卡 | desc/detail/锚点/伪码 | 增加：**关联资产**（图边可点击跳转）、**名称来源徽标**、**契约条目引用**（该节点被哪些契约条目命中/缺失） |

> 双图对照默认复用既有 7 视图与 `diagram.build` 管线，不 fork 第二套 IR（plan-C §11 护栏）。

## 4. 右栏对话（AnalysisChat）

改版后对话从"检索答疑"升级为**认知对齐主界面**，新增三类结构化卡片（沿用现有 `turns.assets` 卡片通道）：

| 卡片类型 | 触发 | 交互 | 对应 plan-C |
|---|---|---|---|
| **提取提案卡** | agent 检索发现资产缺失/过期 | 展示 `范围 + 理由 + 预估资产数`，按钮「确认提取 / 拒绝」 | §4.1 触发提议制 |
| **契约条目固化卡** | 方案讨论中 agent 把期望转结构化 | 逐条展示 `本体类型+锚点期望+行为期望+Z 轴约束+验收方式`，每条可「确认 / 修改 / 删」；未确认条目不进入契约包 | §6.1 对话式固化 |
| **差异报告卡** | runner 完成 / git diff 触发验收 | **通知+摘要卡**：L1/L2 通过率 + L3 待人工条目数概览 + 前三差异摘要（事实/意见分区）+ 「前往验收」跳单元测试页局部验收区块（§5.1）——**判定动作（通过/打回/改期望）统一在验收区块，不在对话内** | §6.2/§6.3 |

交互细节：
- **证据链跳转**：任何条目/差异行的"锚点"或"原话引用"可点击 → 跳源码视图/对话原文位置。
- **事实/意见双通道**：L1/L2 与 L3 视觉分区（如分隔线+标签"事实" / "模型参考意见"），意见区永不混入事实区。
- **角色指示**：输入区旁显示当前角色（提取/验收/归纳/伪码，plan-C §9），busyLabel 复用现有"正在调用工具 xxx…"。

## 5. 需求方案组（三菜单保留，基本不变）

需求方案组三菜单（需求方案 / 任务执行 / 单元测试）保留；唯一功能扩展在单元测试（见 §5.1）。

- **需求方案页**：基本不变。需求详情新增「契约条目」只读区（该需求的契约条目状态机 `draft→confirmed→injected→verifying→accepted/rejected`）；契约条目的**生成与确认仍在方案对话内**（§4 固化卡），不在页面上新开编辑界面。
- **任务执行页**：不变（runner 消费契约包走任务载荷，界面无感）。
- **分析对话**（requirements/analysis）：`diagramSkill`（📐）旁新增 **「期望固化」开关（🧾）**，开启后 agent 在方案讨论中主动产出契约条目固化卡（§4）。

### 5.1 单元测试页 · 新增「局部验收」区块

| 项 | 内容 |
|---|---|
| 定位 | **局部验收** = 契约条目级的符合性检验（与"整体基线变更"区分，后者在影响分析 §5.2） |
| 区块结构 | 与既有单测用例**并列**展示：验收清单（按契约条目逐条 L1/L2/L3 状态）+ 单测区块（现状不变） |
| 验收条目行 | 条目 id + 本体类型 + 锚点期望 + L1/L2/L3 状态徽标 + 「查看差异」（差异报告卡/跳证据链） |
| 触发 | runner 任务完成 / git diff → 严 profile 增量提取 → **L1/L2 自动**；L3 不自动运行——人工主判，条目行提供「激活模型辅助」按钮按需触发（plan-C-M0 §5 决议） |
| 设计者动作 | 逐条「通过 / 打回 / 改期望」；对任一条目可「激活模型辅助」→ L3 参考意见入参考区（带模型来源+置信度+证据，不改变判定） |
| 与单测关系 | 验收条目可**关联**单测用例（后续可由验收条目驱动单测生成，M3+） |
| 差异报告 | 事实区（L1/L2：条目 id+实际资产 id+锚点+差异描述）与参考意见区（L3：模型意见+置信度）双通道分区 |

### 5.2 影响分析（archmap?view=impact）· 新增整体基线变更级追踪

| 项 | 内容 |
|---|---|
| 定位 | **整体** = 基线变更级别（v0→v1）的跨组件变化分析追踪，与局部验收互补 |
| 既有能力 | 基线 diff 视图（现状保留） |
| [新增] 变更追踪 | 跨组件变更扩散链（哪些组件/资产受本次基线变更影响） |
| [新增] 全局漂移 | 契约 ↔ 实现的全局漂移总览（不限于单个契约条目：整体覆盖率、系统性偏差模式） |
| 数据源 | 差分闭环（reconcile 升格的全流程校验器）+ 基线 diff（plan-C §2.2） |

## 6. 命名治理（归属"项目规约"页 /workbench/assets）

> 归属决议：命名规约/术语表**放入既有"项目规约"页**，与架构规约/编码规约同页分区块。规约条目带**场景标签**（提取/验收/命名/通用）——agent 使用规约时**按场景加载相关子集，禁止默认全量注入**（防上下文污染，plan-C §4.1/§5.3）。**实现载体**：`AssetsPage.vue` 是薄壳，实际改造点在其内嵌的 `SpecWorkspace.vue` 中新增分区块。

### 6.1 资产命名规约区块（项目规约页内）
- **列表视图** ✅（M3，`NamingGovernancePanel` 子 tab「命名规约」）：规约条目（规则文本、来源 AI归纳/手写、状态 生效/待确认/待复核/已停用、**场景标签** chips、适用类别），状态筛选下拉；pending 行黄色高亮（AI 归纳提案待设计者确认）。
- **归纳提议卡**：agent 对话内提议入口顺延（induce REST 已就绪：`POST /naming/conventions/induce` → pending 提案，界面确认后 active）。
- **编辑** ✅：手写新增规约（规则文本 + 场景标签多选：提取/验收/命名/通用）、确认（pending→active）、停用/启用、删除。
- **生命周期联动** ✅：`asset_framework._apply_change` 标准变更时规约 `mark_pending_review`（待复核状态已在列表可筛）。

### 6.2 术语表区块（项目规约页内）
- **列表/编辑** ✅（M3，子 tab「术语表」）：词条（术语/别名/定义/来源文件徽标），纯参考；搜索、新增、删除。
- **导入** ✅：从项目文档导入（JSON 数组/对象 或 行式「- 术语: 定义」「术语 | 定义」；越界路径/超大文件/超条数拒绝；source_ref 记录来源文件）。

### 6.3 主 KB 编辑台（多用户模式，本期 schema 留位）
- 主 KB 模式下命名/合并/拆分的**唯一认知层编辑入口**：agent 可携带提案深链进入，人确认执行。
- 展示各编辑的**审计记录**（谁/何时/为什么）；名称变更 bump 版本后，各实例 reconcile 刷新。
- 单机模式下此界面隐藏（编辑在 asset-mgmt 就地完成）。
